# 项目后勤与报销工作台

Windows 本地 CLI：可从 163 邮箱或飞书机器人接收票据，整理网约车和淘宝外卖凭证，再按一列两行生成 A4 打印包。

也可使用本机报销工作台：上传购买凭证截图，本地 OCR 预填信息、分类和查重；按事项管理缺失材料、提交与报销进度。最终总 PDF 打印选择 **A4、1×1**，不要再次二合一。

日常使用请看 [操作指南](操作指南.md)：包含飞书指令、上传步骤、打印设置、文件位置和故障处理。本 README 主要用于安装、配置和维护。当前能力及未完成部分见[项目状态报告](docs/project-status-2026-09-29.md)。

## 当前范围

- 已按真实样例验证可提取文字的滴滴、曹操、享道 PDF；其他平台按通用结构证据判断，证据不足才进入“需要检查”。
- 尚未命名的平台只要具有完整行程单结构、金额一致且能唯一配对，也会以“网约车”名称自动处理，并在费用清单中标记“新平台待命名”。
- 每个网约车票据组包含一份电子发票和一份可含多页的行程单；外卖订单可对应多张电子发票。
- PDF 识别、图片 OCR 和拼版在本机完成；可选 Jev 费用分类会在点击判断时发送筛选后的商品文字和用途，不上传原始票据。通过飞书上传的附件和交付文件会经过飞书服务器。
- 可选的 163 邮箱导入只下载相关 PDF，不删除、移动或标记邮件已读。
- 可选的飞书机器人通过本机长连接接收本人单聊中的图片和 PDF，不需要公网 IP 或域名。
- 淘宝外卖支持订单截图、本地 OCR、邮件正文中的发票图片/ZIP 下载，以及“一份订单对应多张发票”的合计校验；无法唯一匹配时保留原件并进入“需要检查”。
- 第一阶段从 Python 源码运行，不提供 EXE 或安装包。

## 后勤扩展

- **项目待办与辅助消息**：`/logistics` 按项目管理来源群、临时待办和定时照片任务。普通聊天收件器尚未接通常驻采集，消息区用于照片和报销辅助资料。[项目与收件箱](docs/logistics-projects.md)
- **现场照片**：上传、递归读取文件夹、按指定群和日期读取微信本机缓存；本地OCR与可选Jev文字分类后按项目归档，区分原图、普通缓存和待核对记录。微信读取器需另行配置。[照片管理](docs/photo-management.md)
- **定时照片与飞书简报**：后端定时读取，可向已绑定本人飞书账号发送简报及三列照片审阅PDF。需要电脑、微信和服务运行；飞书内添加微信群、手机在线核对尚未实现。[照片简报](docs/photo-briefs.md)
- **固定模板卸货日报**：工作台手动匹配工厂/现场车头照、替换允许的日期和工时字段，使用本机PowerPoint检查并提供HTML预览与可编辑PPTX。通用施工日报、结算报告和人员考勤尚未形成自动闭环。[日报说明](docs/daily-reports.md)
- **查找邮箱发票**：按事项回查历史邮件，提取附件、受支持的淘宝与发票通下载链接；预览后手动关联原事项。[邮箱查找](docs/mail-invoice-search.md)
- **费用分类建议**：固定规则优先，模糊商品文字可交给 Jev；采用后仍须保存、核对，不自动提交报销。[分类说明](docs/expense-classification.md)
- **住宿**：本人飞书指令、草稿确认、幂等写入与回读；房间容量计算已实现，人员变化、酒店经验、多人成员权限和真实登记验收仍需继续。[住宿指令](docs/lodging-usage.md)
- **报销包**：生成总PDF、MD明细及公司模板XLSX。Excel依赖 Node.js、`@oai/artifact-tool` 和自行提供的模板，详见[工作台说明](docs/workbench.md)；仅安装Python依赖不能直接生成Excel。

工作台仅监听本机回环地址，未提供公网部署或手机网页访问。邮件、飞书、Jev均需自行配置；不开启这些集成也可本地登记和整理。

## 开发环境

需要 Windows 和 Python 3.12。克隆仓库并进入目录：

```powershell
git clone https://github.com/qiuC123/invoice-print-layout.git
cd invoice-print-layout
```

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

安装后双击 `打开工作台.cmd`，或运行：

```powershell
.\.venv\Scripts\python.exe -m invoice_print_layout.workbench_web --workspace .\workspace
```

浏览器打开 `http://127.0.0.1:8765/`。不配置邮箱和飞书也能手动登记、上传凭证。识别结果需要核对；目前优先支持淘宝闪购订单截图，其他版式可能需手动填写。

## 公开仓库与本地数据

本仓库仅包含代码、说明和虚构测试数据，不包含真实发票、订单截图、报销台账、个人配置、授权码或历史工作区。克隆后需自行配置邮箱和机器人，数据在本机 `workspace/` 下生成。

验证代码：

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) "src"
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m mypy src/invoice_print_layout
```

## 使用

首次配置 163 邮箱（授权码隐藏输入并保存到 Windows 凭据管理器）：

```powershell
.\.venv\Scripts\invoice-print-layout.exe mail setup --workspace .\workspace
```

只读检索最近 30 天邮件，将发票和行程 PDF 下载到 `待处理`：

```powershell
.\.venv\Scripts\invoice-print-layout.exe mail import --workspace .\workspace --days 30
```

生成打印包：

```powershell
.\.venv\Scripts\invoice-print-layout.exe process --workspace .\workspace
```

首次处理会创建工作区，并提示输入用于输出文件名的姓名。也可以不用邮箱功能，直接把 PDF 放入 `workspace\待处理`。

输出名称示例：

```text
2026-01-15_滴滴_123.45元_张三.pdf
2026-09-03_曹操_52.14元_张三.pdf
```

处理规则和边界见 [实现方案](docs/implementation-plan.md)，项目术语见 [CONTEXT.md](CONTEXT.md)。

## 飞书机器人

已增加本机[项目后勤报销工作台](docs/workbench.md)：双击 `打开工作台.cmd`，按项目登记支出、查看缺少材料、跨天补件、记录提交和到账。勾选“可提交”的事项后，点击“制作报销包”，复用原打印助手排版，生成总 PDF＋MD＋公司模板 Excel；Excel 需要配置本机 artifact-tool 运行环境和私有模板，详见工作台说明。制作成功后所选事项自动进入已提交，失败不改变状态，到账仍需手动确认。飞书支持 `工作台`、`登记 酒店 500 两晚住宿`、`关联 事项编号`、`结束登记`。

先在[飞书开放平台](https://open.feishu.cn/)创建“企业自建应用”，然后：

1. 启用机器人能力。
2. 添加权限：读取用户发给机器人的单聊消息、获取与上传图片或文件资源、发送消息。
3. 设置应用的可用范围，确保自己的飞书账号可使用该应用。
4. 完成下方的 `bot setup`，再运行 `bot run` 让长连接在线。
5. 回到开发者后台，订阅事件 `im.message.receive_v1`（接收消息 v2.0），订阅方式选择“使用长连接接收事件”。
6. 创建并发布一个应用版本，然后在飞书中打开机器人单聊。

一次性保存应用凭据：

```powershell
.\.venv\Scripts\invoice-print-layout.exe bot setup --workspace .\workspace
```

启动机器人：

```powershell
.\.venv\Scripts\invoice-print-layout.exe bot run --workspace .\workspace
```

第一次启动会在电脑显示六位绑定码。在飞书里给机器人发送 `绑定 123456`（以实际绑定码为准），以后只接受该飞书用户的单聊消息。

机器人指令：

日期汇总：`汇总`（今天）、`汇总 昨天`、`汇总 YYYY-MM-DD`。按北京时间的处理日期合并已完成打印包，分类合计后发送总 PDF + MD；不查邮箱、不重复计费、不打断当前收件批次。详见 [按日期汇总](操作指南.md#按日期汇总)。

发送 `帮助`、`菜单`、`指令` 或 `?` 可查看完整指令合集及操作路线。输入框旁的可点击菜单需在飞书开放平台配置，见 [操作指南：快捷入口](操作指南.md#快捷入口)。

```text
打车（只读检查今天的163邮件并自动处理）
外卖（下载今天淘宝闪购发票，等待订单截图）
状态
处理
补发（只补发尚未成功发送的总 PDF 或费用清单）
取消
记忆（生成长期索引摘要并列出超过7天的工作记忆清理候选）
帮助
```

发送“打车”后，机器人只读检查当天163邮件，下载尚未导入的发票/行程 PDF，自动识别排版，最后只向当前单聊发送一份总 PDF 和一份 Markdown 费用清单。总 PDF 按票据组顺序完整追加各打印包，不会跨票据组填补空白半页。当天没有新附件时，机器人才开启手动打车批次；此时可直接发送 PDF，最后发送“处理”。

发送“外卖”后，机器人只读检查当天163邮件并下载淘宝闪购发票文件；随后发送订单截图，再发送“处理”。同一订单的商家发票与平台服务发票会一起计入，只有发票金额合计精确等于订单实付金额且配对唯一时才自动生成。最终同样只发送一份总 PDF 和一份 Markdown 费用清单。机器人保存原始文件，使用飞书 `message_id`、订单号、发票号码和文件哈希去重。

发送“记忆”会收到 `长期索引摘要.md`：它汇总成功票据组及金额，并只读列出超过7天的机器人历史批次或残留临时目录。该指令不会删除任何文件。原始发票、行程单、打印包和异常证据属于留存材料，不进入自动清理范围。

## 顺丰与顺丰同城

- 飞书统一发送 `顺丰`：一起检查今天的顺丰快递和顺丰同城邮件，下载发票及明细，自动识别类型并配对排版，一次返回一份总 PDF 和一份 MD。
- 没有新附件时进入手动收件；可以一起上传快递和同城的发票及明细 PDF，然后发送 `处理`。无需再传 OFD、XML 或截图。
- 顺丰按发票号码及总金额配对；同城按同一批次唯一匹配的总金额配对，多种候选转入检查。不把顺丰邮件导入打车批次。
- 明细连续在前、发票在后，每张 A4 上下两栏，不同票据组不共用空位。保留完整明细和发票内容、原始 PDF 归档；最终打印选 A4、1×1。
- 每轮返回总 PDF 和 MD；费用仍分别计为“快递”“同城配送”。处理后发送 `汇总` 可与今天已完成的打车、外卖等票据合并。
- 无需新增飞书权限。`帮助` 只展示统一的 `顺丰` 入口；旧的 `同城`、`顺丰同城` 消息兼容为同一入口。开发者后台的自定义菜单不会自动修改，菜单只需保留 `顺丰`，响应动作为发送同名文字消息。

## 后台启动与恢复（Windows）

安装当前用户登录时自动启动（无需提供账户密码）：

```powershell
.\scripts\install-bot-startup.ps1
Start-ScheduledTask -TaskName InvoicePrintLayoutBot
```

任务 `InvoicePrintLayoutBot` 使用当前登录用户运行，便于读取该用户凭据管理器中的邮箱和飞书授权信息。后台不弹命令窗口。同一工作区由进程锁限制为一个机器人；程序意外退出后由后台守护程序在 5–60 秒后重启。守护程序自身异常退出由任务计划程序每分钟重试，最多 999 次。

已收到的消息在应答前写入本地 `机器人任务/messages.sqlite3`，重启后按顺序继续；单条失败最多尝试三次。附件已经下载但确认回复失败时，不会再次保存同一附件。关机期间尚未收到的飞书消息不保证自动补收。

票据处理结果和每个文件的发送进度独立保存，每 30 秒检查尚未完成的交付。发送 `补发` 可立即重试；`状态` 可查看待补发数量。飞书请求使用稳定的 UUID 减少网络响应不确定时的重复发送，但超过服务端去重时限的极端情况仍可能重复收到文件，不会再次计费。

如果进程在整批处理完成前退出，程序优先恢复已归档成功的结果，其余材料保留供检查；这类部分完成的批次会明确提示检查。下载失败可发送 `处理` 续办。尚未归档完成的瞬间断电不承诺事务级自动恢复，原始材料仍需核对。

日志位于 `workspace/运行日志/`，当前后台进程状态位于 `workspace/bot-service.json`。停用登录自动启动：

```powershell
Disable-ScheduledTask -TaskName InvoicePrintLayoutBot
```

上述命令只禁用下一次自动启动，不会结束当前运行中的程序。
