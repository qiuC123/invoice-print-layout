# 项目后勤报销工作台（本机首版）

## 打开与日常使用

双击项目目录中的 `打开工作台.cmd`。它会在后台启动本机服务并打开浏览器，无需输入命令。
地址为 `http://127.0.0.1:8765`，仅本机可访问；手机仍通过原飞书机器人传文件。电脑关机时两者均不可用。
不新增云服务、不新增飞书权限，不自动操作财务系统。

1. 点击“批量上传凭证并识别”，一次选择多张购买截图；逐张识别后，点击队列中的图片，对照原图修改预填结果，最后点击“保存全部待保存凭证”，或“仅保存此张”。也可点“手动登记”；没有发票也可以登记。
2. 在事项右侧上传附件并选择用途。后续到达的材料直接追加到该事项。
3. 关注“待补材料”：它明确列出缺少的购买凭证、发票或扣费记录等。可填写开票进度和下次跟进日期；到期只在页面提示，当前不自动发催票消息。
4. 材料齐全后，打开附件核对购买内容、金额、抬头等，再点击“核对完成”。也可勾选多笔后点击“批量核对完成”，确认数量后统一标记；缺材料、非待提交、已经核对的事项会跳过，单笔失败不影响其他事项，并显示原因。包含隐藏的已选事项时会明确提示。成功后保留勾选，方便直接导出。系统只检查材料是否存在，不假装完成发票真伪或金额核验，也不自动提交或标记已报销。
5. 筛选“可提交”及项目后，点击“全选当前列表”，再“制作报销包”。确认报销人和期间，生成总 PDF＋MD 清单＋公司模板 Excel。取消全选仅取消当前列表；“清空勾选”取消所有选择。切换筛选会保留勾选，并提示隐藏的已选数量。全部生成成功后，所选事项自动进入“已提交”；制作失败保持原状态，不自动标记已报销。
6. 报销包制作成功即在本工作台标记“已提交”（不代替实际发送给财务），款项收到后再确认“已报销”。修改已提交事项前先退回待提交。

材料齐全、人工核对、提交报销、报销到账是不同状态。表格和金额卡片按项目／类别／搜索条件筛选。
操作按阶段显示：“待核对”页提供批量核对，点击后在页面内确认凭证内容和金额；“可提交”页提供制作报销包，事项详情只显示“标记已提交”；“已提交”事项提供确认已报销和退回待提交。其他列表不展示批量核对／制作按钮。切换筛选后需选择当前列表中的事项，不继续展示上一阶段的旧详情。
取消事项保留原始材料与操作记录，不删除文件。台账金额以每笔事项的支出金额为准，不按附件数量累加。

### 上传凭证并识别

- 可多选／追加PNG/JPG/WebP截图，每批最多50张、合计200MB，每张最多20MB、2500万像素。使用本机已有RapidOCR逐张处理，不调用大模型、不上传云端。首次加载稍慢。
- 队列分别显示已保存、重复、待保存、失败或跳过。可切换图片修改信息，单张失败不影响其余图片；补填后重试保存不会再次提交已保存图片。重复文件或同一订单在保存时也会再次查重。
- 一张图片对应一笔事项；同一订单多张截图不会自动合并。补充材料请打开已有事项（新标签页）在材料夹上传。刷新或关闭页面会丢失尚未保存的队列，原始文件不受影响。
- 目前规则优先支持淘宝闪购订单截图，预填商家、总实付、订单号、明确标注的消费日期和建议分类。按商品内容区分材料与餐饮，不因来自闪购就一律归外卖；其他版式可能需手动填写。
- 识别结果先预览，未点保存不登记。未知字段留空，金额必须补全才能保存；不把截图时间、文件名日期或开票日期当成消费日期。原图完整保留。
- 同一文件、同一订单号会提示已有事项，不重复记账，包含已提交、已报销及取消事项。仅金额相同不合并。没有订单号的不同截图暂不能保证查出同一笔支出，请人工核对。
- 保存后是未核对的待提交事项；缺发票时出现在“待补材料”。上传凭证不等于材料齐全，更不等于已经报销。
- 发票、支付截图建议先打开所属事项，通过右侧“上传材料”补充。此入口不自动猜测发票或支付截图的归属；原来的飞书收件和打印流程不变。

## 已确认的材料规则

| 类别 | 必需材料 |
| --- | --- |
| 材料采购 | 购买明细／收据 **必需**，再加发票；没有发票时可用微信／支付宝扣费记录 |
| 酒店 | 发票 |
| 高铁 | 12306开具的发票 |
| 外卖 | 订单记录＋发票 |
| 打车 | 行程单＋发票 |
| 顺丰 | 运单明细＋发票（快递和同城使用同一入口） |

材料采购的线上购买凭证为平台订单／商品明细，线下为门店购买收据。仅发票不能代替购买凭证。
购买凭证＋扣费记录显示“材料齐全，使用无发票替代”；后续补到发票后优先采用发票，导出不再重复放扣费记录。
附件用途由人确认，可修正；上传新材料或修改重要信息后需重新核对。
未定义的“其他”类别不会自动判定材料齐全。

## 飞书入口

```text
工作台
登记 酒店 500 两晚住宿
登记 材料采购 128 螺丝及胶水
登记 高铁 123 上海到苏州
关联 事项编号
结束登记
```

登记后机器人回复事项编号，接下来发送的图片／PDF会保存在该事项里，等待在工作台分类。
跨天补材料只需 `关联 事项编号`。原打印批次与事项收件不会混用；有活动打印批次时先完成或取消。
启动原有 `打车`、`外卖`、`顺丰` 指令会退出事项收件。登记项目、消费日期默认为待分配／当天，请在工作台补正。
本首版不自动理解自由口语、不自动猜测附件归属。

## 邮箱和历史记录

- “补收邮件”：只读163邮箱的PDF附件，首次检查当天，此后覆盖上次成功检查日至今天。失败不前移检查日期，已下载文件按哈希去重。只在点击时检查，不后台定时轮询。
- 新PDF进入“邮件收件箱”，由你选择关联事项。当前不自动打开陌生下载链接，也不把未知酒店／材料邮件塞进打车处理器。
- 原外卖命令仍负责淘宝闪购链接下载；工作台补收只收PDF附件，不替代链接下载。
- 原 `打车/外卖/顺丰` 邮箱命令维持原有逻辑；跨天补收使用工作台按钮。
- “同步历史打印记录”：复用原处理记录和文件，不移动、不重做、不重复计费。已验证的旧打印包显示材料齐全，但默认待人工核对，绝不假设已报销；默认项目待分配，日期是原开票日期。
- 旧记录缺少字段时，只使用已有标准打印包命名补全并要求人工核对。缺少文件或无法补全的记录会报告跳过数量，不伪造费用。

## 导出与存储

待提交事项详情提供“建议费用分类”：脚本优先、模糊商品文字交Jev，查看依据后采用，最后点击“保存事项”。结果不会自动核对或提交报销；原始票据不上传，详见 [费用分类建议](expense-classification.md)。

### 制作报销包

- 仅接收材料齐全、已核对、尚未提交的事项。已提交／已报销／取消事项不纳入新报销包；发现所选事项重复订单号或相同附件时停止并提示。尚不等于跨月、不同截图的全面自动防重。
- 首次选择公司模板；当前支持用户提供的“活动运营费用统计表”布局，模板保存在私有 `workspace/工作台/报销模板.xlsx`。换模板会备份上一份。不同结构的模板会明确拒绝，不能随便套写。
- 报销人可修改，报销期间留空则根据已知消费日期填写；未知日期、活动日期、审核签字不猜填。主表费用区只在“现场现金支付（需报销）”列填写分类金额与合计，实际消费金额、公司支付、描述、发票数量及备注等栏留空；无需选择付款来源。原模板名称及表头信息保留，具体购买内容可在“报销明细”查看。
- 已有打印包直接复用；新增打车、外卖、顺丰材料复用原打印助手的识别、裁剪和上下拼版。同一事项顺序连排，不把别的事项填进它的空半页；不支持的格式或金额不一致会提示该事项，修正后再制作。
- 酒店、高铁、材料采购的每个原始页面完整缩放至一张 A4；不自动裁掉购买明细，也不把长截图压到半页。材料采购有发票时优先发票，否则采用已核对的扣费记录。长截图应预览确认文字大小。
- 一次输出同名总 PDF、MD 分类费用清单、XLSX 公司汇总表（附“报销明细”工作表及 PDF 页码）。材料超过模板行数时将余项金额合并到最后一行，全部逐笔明细仍在附表；主表发票栏不自动填写。
- **最终总 PDF 按 A4、1×1 打印**，不要再次二合一。Excel 主表设置为单张 A4，明细表横向按一页宽分页；签字栏仍需实际填写。
- 所有文件成功后才提供下载；失败不发布半成品。原件保留。所有文件生成后整批标记已提交并记录文件名；失败不部分提交。此状态是工作台进度，不自动向财务发送文件，到账仍需手动确认。旧导出结果不追溯改状态。

Excel 制作使用本机 artifact-tool 的 Node.js 运行环境，不调用云端模型。当前电脑自动查找 `%USERPROFILE%/.cache/codex-runtimes/codex-primary-runtime/dependencies/node`；迁移机器时需要提供同样的依赖，或配置 `INVOICE_REPORT_NODE`（Node 可执行文件）和 `INVOICE_REPORT_NODE_MODULES`（包含 `@oai/artifact-tool` 的 node_modules 目录）。没有该依赖时会明确报错；仅 `pip install` 尚不能独立提供 Excel 功能。原 `/api/export` 的 PDF＋MD 接口保留用于兼容。

数据保存在 `workspace/工作台/`：SQLite台账、附件、邮件收件和导出文件。原 `processed.jsonl`、归档与机器人任务不被替换。
备份应在退出工作台服务后复制整个工作区，不只复制数据库。真实文件不提交Git。

开发运行：

```powershell
.\.venv\Scripts\python.exe -m invoice_print_layout.workbench_web --workspace .\workspace
```

第一版只绑定本机回环地址；手机网页访问、团队权限、自动匹配和催票通知不在本次交付范围。

批量上传前端回归：在已提供 Playwright 和 Chromium 的 Node.js 环境中运行 `node tests/receipt_batch_browser.cjs`。该测试拦截全部测试站点请求，使用合成数据，不访问正式台账；后端回归仍运行 `python -m pytest`。

报销制作前端回归：`node tests/report_browser.cjs`；公司模板集成回归需设置 `INVOICE_TEST_REPORT_TEMPLATE` 为本机私有模板路径，再运行 `python -m pytest tests/test_reimbursement.py`，模板本身不纳入仓库。
