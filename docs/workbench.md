# 发票助手与后勤工作台（本机版）

## 自动整理 Agent

原工作台 `/` 已接入 Agent：项目导航、材料合成台、费用核对和打印预览继续使用原页面。同页“自动整理”折叠区显示进度和待确认卡片；侧栏不另设整理入口，`/agent` 仅保留旧入口兼容。独立测试工作区与正式账本分开，手机私人连接白名单不变。

- 每个项目可切换“上传后自动整理”。开启时，原材料合成台接收本批新材料后只创建一个有界Agent任务；关闭时继续原人工合成流程。已关联材料、重复上传及给已有费用补附件不会再次创建费用。
- Agent只轮询自己的任务区；产生结果时延迟刷新原费用列表，人工正在编辑或确认时不会被抢刷。“查看费用”定位原待核对详情；“查看报销预览”使用本次任务明确的费用ID，沿用原打印预览，不混入当前其他勾选或筛选结果。
- 后台邮箱自动收件可独立暂停，暂停保留本机当前邮箱配置与凭据。原材料合成台“补收邮件”仍使用同一个已配置账号，主工作台会显示账号及收件状态。

- 上传先保存原件，再创建显式指定项目及最多20份材料的任务；离开页面后后台继续。已关联、跨项目或移除的材料不能进入新任务。
- 明确唯一的金额与店铺组合走本地规则。复杂问题可由已配置 GLM 返回限定的 JSON 工具请求，程序校验后执行；首版使用现有模型适配器，不依赖外部 Agent 框架。默认本地识别，模型选项须在开始前启用，原件图片不会通过此规划接口上传。
- 工具包括本地识别、查看原文、扫描完整竞争池、复核实付组成、验证组合、建立未核对草稿、生成完整 PDF/XLSX 预览和请求补充。模型不能直接执行 shell、改数据库、核对通过或正式提交。
- 组合按既有类型要求验算：铁路/住宿完整单发票、打车发票与行程、顺丰发票与明确对应的运单明细、采购或餐饮明细与发票，以及允许的凭证与付款。金额只能计一次。程序先从本地版面定位买卖双方、商品/数量/折扣、实际店铺、服务说明、收款平台及支付渠道；不让模型按PDF文字出现顺序猜左右角色，不把推荐广告或适用设备当采购内容。
- 本地严格规则不足时，`investigate_relations`让已配置GLM在程序限定的完整候选中结合商品、金额和商家角色判断。具体商品相容、可辨认的宾馆名称、饮品加配送分票等可以形成明确标注“推断、待核对”的草稿；引用须本地核实，金额、类型缺件、全池竞争、原件/人员/交易防重继续由工具独立校验。平台收款与实际开票方可以名称不同，但模型不能据此新增已确认商家别名。
- 付款只写平台和同额、存在多个可行组合等确实缺对应事实时，页面显示这几份原件及商品/商家/金额，提供“确实同一笔，继续生成预览”或“不是同一笔，先保留材料”。回答绑定问题ID、材料版本、SHA及整个材料池快照；只为此组保存不可变用户确认回执，随后同一任务继续验算、分类、命名与报销预览。否认则停止该假设，不反复追问；确认不表示已核对、提交或增加预算。
- 用户关系确认不能覆盖明确商品矛盾、金额错误、无法完整读取或缺少必要原件；这些情况须补材料或回人工工作台。调查返回无据引文或无效JSON时，保留可回答的具体问题，避免重复调用失败工具。完全相同的观察继续复用工具回执，新增模型观察/用户回答会使相应检查重新计算。
- 完整本地组合仍待对应事实确认时，先保留整组问题，不抢先登记其中的单票子集。旧任务若已生成单张完整酒店发票草稿、剩余付款没有确认选项，可在同页点“重新检查对应关系”；程序只为该任务自己生成、未核对且未人工编辑的草稿重新校验原件和版本，形成正式确认卡片。确认后将金额守恒的付款关联到原费用，保持费用编号和金额、原任务及累计额度，再继续报销预览；重复执行不会增加费用或附件。重新检查本身不代答、不核对或提交，也不放宽缺件、交易重复和竞争材料限制。
  - 若旧任务已经按真实确认补齐原件，却因历史进展记录停止，可点击一次“按剩余额度重试”。该入口再次核实持久确认、补材记录及当前原件/费用，保留累计额度；已有人工作出修改、缺少确认链或已使用过本次续跑时不能采用此方式。商品与分类结果同时绑定原件摘要，避免把补材后相同商品误判为无进展。
- 草稿建立后继续调用商品提取、费用分类、报销命名工具：只从购买材料的明确商品标签、发票项目或有边界的商品区提取内容，保留原文位置及原件摘要；商家名、付款备注和收货地址不作为商品。先复用本地规则及人工经验，必要时使用已配置Jev只判断商品文字的类别；GLM继续负责调查工具选择。Jev与GLM共享任务模型预算，图片不通过分类接口上传。
- 具体报销名称由已提取商品及合法模板分类生成，例如“鼠标采购”；人工名称及分类保持优先。缺商品、混合类别、低置信分类或材料/人工经验发生变化时，保留草稿并提示人工补充，不把占位名称当成整理完成。页面和最终PDF/XLSX均使用保存后的具体名称。
- 商品标题按连续内容处理换行，并区分适用设备描述与独立购买项。只有“超市服务”等通用类别时不能推断出某件具体物品。明确完成的提前送达、送至暂存点等表达可作为完成状态依据；待配送、退款、取消与金额不足的记录继续阻断。
- 关系调查、商品提取和命名共用原件事实，保留多商品、原文、页码、坐标及原件摘要，不再在分类时重提取一次。脚本能识别的清单直接使用；明确商品区域仍有缺项时，才尝试一次文本模型补提取，返回完整行覆盖、连续原文名称及逐字引句，程序独立核验。原文只有泛称、商家或付款信息时不猜商品；混合类别及截断清单继续请求人工处理。
- 原件事实缓存在当前工作台的独立 `agent-material-cache/facts.sqlite3`，有数量和载荷容量边界。商品补提取尝试保存在 `.cache/agent-goods.sqlite3`，作为防重复请求的持久收据保留。二者绑定原件内容、材料/人工版本、解析规则及模型提示版本。命中仍校验原件SHA，失败不冒充成功；负结果及已尝试状态防止无依据的反复请求。原人工字段和写入前的金额、版本、交易防重检查保留。
- 高级组合按目标金额和证据关联分组，有界枚举并审核整个项目中的竞争材料；不因整池超过旧20/40份限制就忽略小组，也不截取前N份假造唯一。明确同来源域订单号与金额守恒由脚本直接整理；明确缺材料或模型无法补足的关系事实直接询问，避免无效模型调用。
- 任务API的 `job.timings` 记录规划、指纹、各工具及有界模型补提取等阶段次数、耗时和缓存信息。各阶段为包含子步骤的独立计时，不能相加当总耗时；`active_seconds` 沿用原预算活动时间，用户确认等待单列。计时写入遇到业务事务锁时仅缓冲，外层完成后保存，诊断不阻塞或改变费用、预算与确认收据。
- 每任务累计最多6次模型调用、48次工具调用、180秒活动时间；两次连续无新结果则停止。额度在请求前持久化，刷新、重启和回答问题不重置计数。后台子进程由独立线程监督，超时或取消后强制结束；非正常退出记录失败，避免自动无限重试。
- 网络错误最多自动重试一次；规划器返回无效工具协议、关联调查返回无效 JSON 或不可复核引文时，转为程序根据原件生成的具体事实询问。通用商品发票缺少购买明细时，不以付款商品说明代填，也不提供直接确认组合的选项。失败任务可显式按剩余额度重试；无进展停止的任务必须先补充或修正材料。重试不清零调用计数、网络重试次数和累计耗时，也不与同项目另一任务并行写入。
- 酒店费用已绑定的付款截图会与发票一并进入报销预览和打印包，金额只按该笔费用计一次；仅有完整发票的既有路径保持。
- 模型转人工请求允许附带可选问题文字，实际提示仍由程序依据当前材料生成；调查工具被拒绝时保留失败观察，供模型在剩余额度内改用其他调查或正常转人工。越界材料不会被读取，未经验证的写入继续拒绝；重复同一失败调查同样受无进展与总预算约束。
- 模型额度耗尽后，只在仍有工具额度时整理具体缺项；任务保持停止，提供人工入口，不再调用模型、提供继续答题选项或重置额度。已关联的本任务发票仍用于说明上下文，不会因剩下付款材料而重复要求上传已有发票。
- 草稿与写入回执在同一事务内保存，未知写入结果先读取回执；创建前重查整个项目材料池、原件摘要、版本、交易防重和人员。人工字段优先。缓存包含程序版本、材料池、费用/附件和模板指纹，变更后须重新验算。
- 支持有证据的实付金额纠错、同店同额的商家订单号区分，以及完整材料池中的合并/分次付款和上述有据关联推断。优惠和费用组成必须与原文实付整数分验算一致；退款、跨费用分摊及缺少实际商品/商家对应的记录继续请求补充，不猜测差额。相似订单截图可以保留为同一草稿的待核对视图，不删除原件、不计成第二笔；付款记录不按精确时间去重。
- 预览不代表人工核对或财务送达。最终核对和制作正式报销包仍通过人工工作台。

本机 API：GET /api/agent/jobs?project=…、GET /api/agent/job?id=…、POST /api/agent/start、/api/agent/answer、/api/agent/refresh-question、/api/agent/cancel、/api/agent/retry。重新检查须传当前 `expected_updated_at`，过期或不适用的请求拒绝。写操作沿用本机 Host/Origin 与 X-Workbench-Token 校验。任务、动作缓存与回执只保存在忽略目录中的工作台 SQLite。

## 打开与日常使用

高铁报销仅需12306发票，支付截图不作为必需材料。原文明确为12306购票或铁路客运票款的支付截图保存在合成台“归档”区，原件仍可查看，不进入付款选择、建议组合或新增费用。归档内可删除到“已删除”，也可恢复回归档；铁路付款不能恢复到合成选择区。铁路发票仍可单份确认创建，在“车费／火车、飞机”分类下只需发票即可进入待核对。不会仅凭文件名、金额或“铁路”商家名排除中铁物流等其他付款。

只处理票据时，双击项目目录中的 `打开发票助手.cmd`。它在后台启动独立发票模式并直接打开页面，无需先进入后勤项目页。

本机桌面也已提供“发票助手”快捷方式，直接双击即可打开独立版。

独立模式保留图片/PDF上传、现有邮箱检索、项目台账、材料缺项、人工核对、报销预览及PDF/Excel制作；不加载现场照片、日报、微信群任务和后台照片调度。收材料入口统一放在“材料合成台”，顶部重复上传按钮和主工具栏的补收邮件已移除。侧栏保留“新建项目”、具体项目和“未报销／已报销”分类；任一项目页都能新建，创建后打开新项目，原项目与费用保持原状。窄屏的新建入口移到顶部。

在左侧项目上点击右键，菜单提供重命名、置顶／取消置顶、永久删除和移到已报销／移回未报销。键盘聚焦项目后按Shift+F10也能打开；Esc或点击外部关闭。报销分类保存后，项目会进入对应侧栏分类，数量同步，刷新和重新启动后保留；每笔费用的金额、材料、核对及提交阶段保持独立。工具栏不再另设项目报销状态。

重命名和置顶保存在发票工作台，项目ID保持稳定；后勤项目目录不变。永久删除需在页面确认，将移除该项目的发票台账、收件记录及材料关联，工作台无法恢复；原始文件仍保存在本机，后勤项目和其他项目的记录保留。

账单、原件、项目ID和模板沿用原本机workspace，不另建一套账。独立启动只打开已有账单，不自动导入历史、收邮件或整理旧材料；收件及历史同步仍由对应按钮启动。

费用行右侧提供“迁移”和“删除”。迁移选择其他项目，费用金额、发票、付款及补充材料一起保留，迁移后进入待核对；已合成的多对多材料关系也随项目归属同步。删除将费用移到“已删除”，正常列表与报销汇总不再计入，原件保留；在“已删除”中点“恢复”可找回，原来已取消的费用仍保持已取消。已提交、已报销的费用须先退回，再删除或迁移；已经合并到其他费用的旧成员不单独操作。

需要照片、日报等后勤功能时，双击原 `打开工作台.cmd`。两个入口使用同一个本机端口和workspace单实例锁，启动器会先等待原模式的操作结束，再优雅切换到所选模式。同一工作区只运行一个模式，避免两套服务同时改账。
地址为 `http://127.0.0.1:8765`，仅本机可访问；手机仍通过原飞书机器人传文件。电脑关机时两者均不可用。
默认本机处理，分别提取购物平台、实际店铺和支付渠道，配对使用本地平台、实际店铺和金额规则。淘宝闪购是购物平台，具体便利店是实际店铺，支付宝／微信支付是支付渠道；银行卡只表示扣款来源，不能据此猜测支付渠道。平台使用原文明确名称或“感谢你对淘宝闪购的信任”等字样识别，不仅凭图标或颜色推断。仅在本工作区明确启用GLM后，核心信息不足时的辅助识别使用智谱标准API，不新增飞书权限，不自动操作财务系统。

本工作区按用户授权启用GLM-5.3-Flash，2026年10月13日起改为本地规则主配对、AI按需辅助识别。批量上传先保存原件，原生PDF优先直接提字，图片先本地OCR；明确角色、金额、销售方或收款方及付款状态已能确定时，直接使用本地结果，不请求模型。类别或消费日期缺失不阻断已明确的金额与商家关系。关键信息不足时自动尝试GLM，文字缺失时可读取页面图；合成台不再提供手动“AI辅助识别”按钮，真正读取失败仍可重试识别或手工补齐材料信息。人工修改和确定的原生PDF关键字段优先保留。自动扫描不调用GLM判断，金额相符且来源可用的组合先展示在材料合成台的“建议组合”；名称不同或多个合理组合会注明核对原因。商家名称识别不同可对照原件人工确认；退款、金额、票号、付款状态或材料用途的核心冲突仍不推荐。只有人工确认创建后才进入“待核对”，不自动核验或提交。

建议按实际店铺或原文商品说明、购物平台与金额综合判断，保留具体分店，仅统一空格、全半角和明确的“闪购”标识前缀。下单时间与支付时间含义不同，配对不提取精确交易时间，不按时间评分、排序或显示缺失/间隔警告；报销所需消费日期及原件中的时间文字保留。平台业务订单号、支付订单号、商家订单号与支付交易号分别保存，缺号或不同体系编号不同均不直接报错；只有同类型、同明确平台或渠道的编号用于防重复。没有明确体系的旧编号保留展示，不作强制相等判断。订单和付款可以共同证明一笔费用，但同笔付款不能因上传两张不同截图而重复计费。所有金额相符的竞争组合仍参与歧义判断，平台不同或排序靠前均不会把多种可能变成唯一；新增材料或所选依据改变后旧确认失效。

商家冲突显示中文“商家名称”或“实际店铺”，新识别记录保留“本地识别／AI补读”的两值供对照；平台名和店铺名各归其位，不能仅因两者不同就报商家冲突，实际不同分店仍须核对。括号、空格等规范化后相同的店名不报冲突；旧冲突标记若有本地和AI两份同源原文引据证明与当前店铺一致，则只读消除该活跃误报，不改写历史记录。无对照证据或确有不同两值时仍保留核对，不重造历史结果。识别到名称不同不会改写人工值或原件，也不会自动把材料合成费用。

启用配置为私有 `workspace/工作台/invoice-ai.json`，内容如 `{"enabled":true,"secret_env_file":"C:/private/ai-secrets/glm.env"}`，只存开关及密钥文件位置。密钥仅从 `GLM_API_KEY` 环境变量或指定文件同名变量加载，不进入源码或页面。实际触发辅助识别时，必要的材料文字或页面图会发送到智谱API，原件仍保存在本机；清晰材料的本地识别与算法配对不发送材料。关闭 `enabled` 后重新启动发票助手即可只使用本机识别，算法配对仍可用；未配置的其他工作区保持本机默认。

1. 打开“材料合成台”，用“收材料”混合上传PDF、发票／收据图片和付款截图，或点击“补收邮件”。邮件与上传都先保存原件、再整理当前项目材料，不直接创建费用；不再另设“手动登记”。补收也读取淘宝闪购发票通知中明确的正文发票链接，链接返回二维码图片时保存原图，再尝试领取正式PDF；普通装饰图片不收取。二维码图片可随材料上传，链接用合成台的“二维码／链接领票”页面表单粘贴。领取失败可重试；PDF已保存而整理失败时，只重试整理，不再次领取。
2. 在材料合成台点击“寻找合成组合”，建议直接出现在左侧；点击一组，右侧预选材料并显示完整原件、金额、推荐理由及名称或竞争警示。确认项目类型、金额和项目名称后，点击“确认合成并进入待核对”，成功后自动关闭合成台、进入待核对并选中新费用，费用复选框不跨阶段残留。建议覆盖当前项目材料，不受弹窗后方的费用筛选或搜索影响；若新费用被原筛选挡住，会清空筛选并说明。没有建议时仍可在下方手工选择任意单份或多份材料；版本变化后须重新选择。
3. 点选费用，右侧显示实际A4打印页，可放大／下载矢量PDF。再次点击当前费用行，或点击列表、两栏间隔、预览边缘等空白处，可取消预览选中；批量复选框的勾选不变，筛选及滚动位置保留。操作按钮、输入框、弹窗及原件内容不会误取消。展开“材料夹”上传附件或选择用途，后续材料追加到同一费用。材料不齐时也展示已收材料预览及缺项提示。

4. 在“待核对”检查购买内容、金额、抬头等，点击“核对完成”；也可勾选多笔批量核对。缺材料、非草稿、已核对事项会跳过，失败单笔显示原因，不影响其他事项。系统只检查材料存在性，最终核对由人工完成。

逐笔处理时可点击“核对并下一笔”：只核对当前费用，保留人员、类别、问题和搜索筛选，在待核对中打开下一笔并保留列表位置。缺材料时先列出费用、金额和实际缺项，用户确认“仍然核对完成”后进入可提交，取消则不改费用。批量核对也会逐笔列明缺项并要求明确确认，不静默跳过或默认放行。确认缺项不等于材料齐全，缺项持续显示；金额待确认及未选择具体类别仍须先修正。当前范围处理完会明确提示。保存失败保持当前笔，保存成功但刷新失败不会重复提交。原“核对完成，进入可提交”入口保留。
核对成功会取消对应费用的复选框勾选及原行高亮，失败费用和其他勾选保留。

5. 已核对费用进入“可提交”，可直接查看最终打印页并制作报销包。确认报销人及期间后生成总PDF、MD清单和公司模板Excel；全部生成成功才登记包文件，失败保持原状态。历史已生成包和已报销费用也在可提交保留，原账单状态不迁移。费用级已报销页签及确认按钮已移除，项目级未报销／已报销分类独立保留。
可提交页提供“退回待核对”：仅处理当前可见且已勾选的费用，确认前列明笔数、金额及隐藏勾选不参与。整批当前版本及项目校验通过才退回，任一冲突整批不改；退回保留金额、归属、原件和旧报销包，撤销本次核对及缺材料确认，需要重新核对。成功退回清除这批勾选，隐藏勾选保留，取消或失败保持选择。

6. 只在“可提交”中选择已核对费用制作报销包。切换筛选保留勾选并提示隐藏的已选数量；复选框可逐项取消，或取消当前列表的全选。制作报销包不等于向财务发送，程序不自动确认到账。

打车按正式发票＋行程单准备材料，两份齐全时不要求付款截图。历史合成费用即使保留“发票／收据＋付款截图”设置，也按此打车规则检查；明确选择“仅支付凭证”及历史打印包保持原规则。没有人工指定用途时，原生PDF内容能证明为行程单的旧“待分类材料”，浏览时按行程单显示，原记录及原件保留；人工选定的用途优先。滴滴、腾讯、高德及享道等已验证行程单按正文边界去除空白和装饰，行程在上、发票在下；单页原件能容纳时合为一张A4，较多行程保留所需页数。多页发票须有同一票号、开票日期和完整连续页码，可从末页小写金额位置读取价税合计；全部发票页完整保留，能容纳的相邻页合排，长页各占一张A4。同一张两页发票的短续页若提前与行程续页合排能减少纸张，会在打印副本中优先合排；不能节纸时保留原顺序，行程单页序及原发票页码始终保留，不与其他费用混排。正文、附注、二维码和印章保留，仅删除已确认的广告；未知图片完整保留。原件与保存时不一致、边界不明确或金额对应关系不明时要求检查。待核对预览、公司报销包及材料导出共用同一矢量拼版，不自动核对费用。


主页面仅保留待核对、可提交、已删除三个页签，顶部金额卡片为待核对与可提交；材料与建议组合统一在材料合成台处理。未核验草稿在待核对中查看，缺材料的也保留原金额、附件及缺项提示；核对缺材料费用时仍需明确确认缺项。已撤回材料配对的费用只回材料合成台，重新确认合成后再进入待核对。事项内容、项目或附件改变后，需要重新核对。取消或合并的旧记录保留在已删除视图，不计入待核对金额。

待核对详情提供“修改报销信息”，可修改金额、项目类型和项目名称，分类与名称遵循创建时同一二级关系。保存后仍须核对，原票金额、商家、附件与来源记录保留；没有补齐材料时仍不能核对完成。编辑失败保留已填表单，费用版本冲突时需要重新打开当前费用。

材料齐全、进入待核对、人工核对、提交报销、报销到账是不同状态。表格和金额卡片按项目／类别／搜索条件筛选。
“待核对”页提供批量核对，完成后到“可提交”制作报销包。制作要求已人工核对、尚未生成历史包，且材料齐全或已有仍有效的缺项确认。确认绑定当前费用及原材料，金额、分类、归属或材料变化后需重新核对；不能沿用旧确认绕过新缺项。已确认缺材料的费用只打印已收原件，Excel和清单明确列出缺项，不制造凭证；无材料的费用标为“无材料”，若整包都无材料则提示无法生成打印页。历史包在可提交保留查看。切换筛选后只展示当前列表中所选费用的打印预览。

桌面工作台顶部信息、指标与筛选栏固定；人员金额、材料合成台和报销预览集中在筛选栏右侧。左侧阶段标签和批量操作固定，事项列表与右侧预览各自滚动，滚到边界也不会推动另一栏或整页。各栏保留滚动条占位，切换阶段宽度保持一致；手机保持单列自然滚动。工具栏的外观模式可切换浅色／深色，本浏览器会记住选择；原件和报销打印纸张保持自身颜色。

人员金额、材料合成台和报销预览点击后立即开窗，在窗口内显示加载状态。读取失败时可在原窗口重试；只读加载期间可点击关闭或按Esc，重新打开会读取最新数据。加载完成后再启用对应的材料操作、打印或下载。

弹窗右上角统一使用居中的×关闭按钮，底部取消和保存保留各自操作含义，处理中仍按原有规则锁定关闭。浅色采用白底与蓝色强调，暗色采用中性黑灰及灰白选中、按钮和焦点；顶部指标卡使用相同的普通边框。
取消事项保留原始材料与操作记录，不删除文件。台账金额以每笔事项的支出金额为准，不按附件数量累加。

### 材料合成台

左上是未匹配的发票／收据，左下是付款截图。已付款的平台购买记录也按收据放在①，标为“收据 · 平台购买记录”；已有订单／购买用途及完成付款证据可直接展示，无需重新识别或补订单号。原始用途和存疑提示保留，人工指定用途、待领票二维码及未付／失败／退款材料不自动改类；商家、金额等冲突仍须核对。合成台使用当前侧栏项目，不再重复提供项目下拉；从根页进入时先在侧栏选择项目。桌面左右各自滚动，顶部操作区保留；滚动材料列表不会移动右侧表单和预览，右侧原件可独立滚动。窄屏改为上下自然滚动。两侧及其他普通材料均可多选，再次点击取消；右侧显示选中原件、票据合计、付款合计和差额。只选发票、付款或一份普通材料也能创建费用，不要求两侧齐全或金额相等。选好后先展示机器识别对应的项目类型、金额、项目名称；这三项都要明确才能点击“确认创建报销项目”。未知金额先留空，填写后才能创建；原识别内容保留。

项目类型按最终《活动运营费用统计表》提供拓展、车费、生活费、人员、现场购材料、其他。项目名称随类型联动：前四类只能从对应的表格细则中选择；现场购材料和其他可以自行键入项目名称。保存接口也检查必填及二级关系，确认后仍是未核验草稿，缺材料继续标记待补。

同一项目由统一负责人制作一张公司报销表。每笔费用另存“费用归属人”，与微信提交人、发票销售方及报销表负责人分开。合成台可继承已标记人员，也可明确选择费用归属人；待核对费用可以修改归属。来源昵称和稳定发送者身份保留，不能靠发票上的姓名或商家推断归属。旧费用未指定时单列，不自动算到负责人名下。

项目“人员金额”按有效费用ID各计一次，区分待核对、可提交和已制包金额。发票、行程单、付款截图等附件不重复累加；删除、取消、合并、归档及撤回到合成台的费用不参与当前汇总。尚未确认创建的材料也不计入费用金额。不同归属人的材料不自动配对或合并；手工确认时应明确费用归属人，原件和提交来源不变。

“人员金额”表中姓名是一个可输入下拉框，直接输入新名字，按Enter或点击出现的“保存”提交；移开焦点不会自动保存。点击同框箭头或按Alt+下箭头展开已有名单，选择人员后检查两边笔数与金额，再确认归并。输入恰好与已有姓名相同不会自动归并，需要从候选中选择；候选按人员ID识别，选择自己不会写入。同人不同昵称归并后，费用各计一次，原昵称和提交身份保留；改名沿用原人员ID。费用金额、分类、消费日期和核对状态保持，已保存的报销包仍保留生成时的快照。选择或新增人员时也可以直接选已有人员，不必重复创建。

类别、人员和问题三个筛选框使用可勾选的多选菜单。每个框可同时选择多项，同框内满足任一项即可，跨框及搜索条件需要同时满足；三个菜单顶部均提供“全选”勾选项，一次勾选该框全部有效选项（人员包含未指定），全选后可逐项取消不需要的类别、人员或问题；部分勾选时全选项显示半选状态，再点击全选可补齐。取消全选或取消所有选项会清空该框勾选并恢复该框全部范围。顶部默认及全选时分别显示所有类别、全部人员、所有问题；不设置全选快捷键或快捷提示。点击空白处、切换菜单或按Esc收起，箭头与控件垂直居中。人员可选未指定或已有人员，与类别和搜索一起筛选费用。人员按稳定ID识别；材料合成台的建议独立显示当前项目材料，归属不一致或尚待确认时必须人工选择，不根据其中一张猜人。名单改名后仍保留同一人的筛选；归并或移除使部分人员筛选失效时，只移除失效项并提示，保留其他人员及类别/问题选择。

问题筛选可选“缺材料”“金额有差额”“材料已齐”，与人员、类别和搜索共同限定费用列表、金额卡片及未勾选时的报销预览。缺材料按台账缺项判断，金额待确认不冒充缺少材料；差额只比较已知的原材料金额。材料已齐不代表金额已确认或人工核对完成；打车仍按发票＋行程单判断，不要求额外付款截图。材料合成台的建议组合不受主页面费用筛选影响。

人员金额表中的笔数和金额可点击，展开该人员、对应金额口径的逐笔明细，并显示数量与合计；点击具体费用即可定位工作台中的原费用和打印页，同时按该人员筛选。返回可继续查看人员汇总，姓名框仍用于改名或选择已有人员。待核对、可提交和已制包分别计算，已制包不代表款项到账；未指定只包含尚未填写归属人的费用。

未指定费用可能属于多人。在待核对先按未指定筛选，分批勾选属于同一个人的费用，点击“修改归属”，选择名单上的人并确认保存；只修改当前可见勾选，每次最多200笔。保存不合并费用、改金额或完成核对，任一版本或状态变化整批不提交。合成台可选多份尚未关联的材料后点击“指定材料归属”，金额、用途和选择保留，不创建费用；已有费用应回到待核对修改归属。

待核对还可勾选费用后点击“修改项目类型”。改为“现场购材料”或“其他”时，每笔保留自己的项目名称（缺失时沿用原费用标题）；改为有固定细则的类型时，明确选择该类型对应细则。类型及报销分类一起更新，原费用标题、金额、人员、日期、原件和核对状态保留，各笔仍独立。只处理当前可见勾选，每次1至200笔；任一费用版本、状态或名称无效，整批不保存。成功后刷新失败只重试读取，不重复保存。

没有费用或材料引用的人员可以移除，并从“已移除人员”恢复。有引用的人员应先归并；未指定归属的费用仍单列，不自动算到某人名下。姓名修改及归并只作用于当前项目，名单或材料变化后需重新打开操作。

公司主表继续使用原分类规则和统一负责人；同一个Excel的“报销明细”末列增加“费用归属人”，同包Markdown附每人汇总与逐笔费用清单。人员合计与同批公司表总额一致。工作台只记录归属和报销费用，不记录是否垫付，不增加结算方式设置。

自动扫描在同项目的全部新旧未匹配材料中检索，每组最多4张票据和4张付款，按整数分比较合计，支持一对一、一对多和多对多。金额相符且来源核心信息可用的组合显示在合成台建议列表；商家明确对应、名称关系需核对、存在竞争组合分别提示，不能把金额相符说成已确认对应。退款、未明确付款成功及核心金额／商家冲突不推荐。付款时间与开票时间不要求相同，票号用于去重，不要求与支付编号相同。通用数电票从原生PDF销售方栏补读商家，不凭文件名猜关系；不明确别名不自动认定。候选扫描只读且不调用模型、不创建费用。超过20份票据／32份付款或50000组合时显示原因；展示最多100组，竞争判断使用完整材料池。全部项目逐项目扫描，不把跨项目金额凑成组合，归属未定材料仍留手工处理。确认创建前及事务内复验完整竞争材料、全池快照和原件；新增或修改材料会让旧候选失效，不能重试后悄悄采用新组合。已配对材料移出未匹配池，在“已配对”区可撤回；费用侧栏也提供“撤回材料配对”。多票组撤回恢复原有费用与附件归属，新票据和付款回到待匹配区，组合费用取消并保留记录。原单票组撤回仅解除新增付款关系，票据费用保留。已核对、已提交或被后续编辑的组合不覆盖撤回。

普通识别使用本机OCR和PDF文字读取。当前自动领票支持上海、江西税务官方二维码入口，仅请求指定领票服务；保留二维码来源及正式PDF关联。未知、过期或需要登录的二维码列入“待领票与其他材料”，可重试领取或手动上传正式PDF。二维码截图不作为发票计入材料完整性。

发票号码用于检查重复材料，不用于和付款截图配对。本地或OCR明确读到唯一票号后复用该值，不要求模型再次返回号码。模型识别不足材料时，同次返回文字和字段；程序仅从带“发票号码”标签的文字核对号码，避免采用税号或交易号。可选票号未确认时忽略该值、保留正确金额和商家，不把整份识别标为失败。确实有多个发票号码或原件字段冲突时仍需人工处理，不能据此自动归为同一票。

“重新识别”对应真正的提取失败；本地完整读取金额、商家和必要票号/付款状态成功后，会清除旧AI失败提示，关闭AI时也适用。材料不再显示“商品不明”，历史材料中的这项旧提示也直接隐藏，无需重新识别。确实缺关键字段、识别范围不完整或存在冲突时，仍保留人工处理提示。

自动AI补读只提取单份材料的金额、商家、票号、购买内容、日期及适用的付款状态，结果是可核对的字段建议；它不判断票据与付款是否对应，也不创建、核验或提交费用。商品说明和付款备注有则保留作原文配对参考，缺失不报错，不要求为了补齐可选内容再次调用模型。材料编辑只确认材料角色、金额及可选名称；报销分类统一在右侧确认创建时选择项目类型及对应项目名称，两项和金额仍须确认完整。高铁原文识别和无需付款的材料规则保留。

原生PDF提字、本地OCR及字段规则优先；明确角色、金额、店铺或销售方、必要票号和付款状态后，已完成订单也可直接使用本地结果。购物平台、支付渠道、交易编号、商品说明或日期等可选信息缺失不单独触发LLM；核心信息仍不清楚时才准备必要原图补读，保留LLM兜底。

本地名称映射把明确的打印制作、打印服务、打印费、复印服务、图文快印等交易明细建议为“其他／打印”；饮用水、矿泉水、纯净水等明细建议为“生活费／现场饮用水、夜宵”。规则读取已保存的票据明细或商品说明、付款备注，不需要再次识别或经验积累；不会仅凭“广告传媒公司”等商家名称或“娃哈哈”等品牌名推断用途，也不覆盖已保存的人工名称。商品优惠、负数减项及附带派送行不重新改变原识别总金额。建议需人确认后保存，缺少这些可选明细不会影响配对。

### 材料归档与恢复

未关联费用的发票、收据、付款截图及其他材料均可点击“归档”，移出选择区和配对候选。归档不新增费用，也不改变材料的金额、识别内容或所属项目。已关联费用的材料先撤回关联后才能归档。

撤回后保留的原票费用也提供“确认金额／用途”和“归档”。“待配对：付款截图”表示尚未选择对应付款，不是在描述发票类型。确认金额可修正费用中保留的金额和可选用途，原票文字、商家和来源保留；归档、删除、恢复均不释放原票的去重身份。归档删除可恢复回归档，再恢复到合成台；仍属于活动组合的票据须先撤回组合。

“归档”区可查看原件、恢复普通材料或删除。删除是可恢复的：材料进入区内“已删除”列表，原件和去重记录保留；点击恢复会回到归档，不会自动重读、配对或创建费用。重复上传同一份原件不会把归档或已删除材料重新放回选择区。

### 合成台多组确认

合成台左侧建议组合可逐项勾选／取消，也可全选当前组合。点击一组就在台内右侧预览，票据与付款完整展示，可打开原件放大；不再往返主页面。点击“确认选中组合”后，逐组确认报销项目类型、对应名称和金额，再一次创建为待核对费用；成功后自动关闭确认窗和合成台，选中第一笔新费用，不自动核对或提交。竞争组合共用材料时不能一起确认，版本变化会取消过期勾选；创建失败保留表单，已创建但刷新失败不再次提交。

共享同一份材料的竞争组合不能同时合成。提交时重新检查候选版本、原件及材料状态，任一组合失效时整批不创建费用，需要重新选择当前候选。网络失败保留确认表单供重试，同一批请求重复到达也不会重复记账。

主工具栏和合成台不再显示项目筛选，项目从侧栏进入。“制作报销包”只在“可提交”页提供，勾选的费用须已核对，材料完整或已明确确认现有缺项；其他页签的选择不能借此导出未经核对的材料。

“按金额一键配对”用于已查看材料并愿意仅以金额确认对应的情况。先展示当前项目的唯一组合和跳过原因，再统一确认进入待核对；这次确认允许商家名称不同，仍需之后核对用途与原件。优先一票一付款的唯一金额组合，再处理剩余无法拆分的唯一合计组合；同金额有多种配法时留手工选择，不把全部材料合成一笔。归档、退款、未确认付款成功、金额冲突、原件失效等不能借此自动配对。原配对扫描仍按原关系规则运行。

金额确认会复验完整材料池、原件与版本，任一变化让旧预览失效；整批事务提交，同一确认请求重复到达也只保存一次。名称和分类采用明确的原有或明细建议，未知用途先用“其他／待核对费用”，可在待核对中修改；不会自动核对或生成报销包。

### 单笔最终打印预览

点选费用后自动复用正式报销包的单笔排版器生成 PDF，并在侧栏显示实际 A4 页面图；放大／下载入口打开同一矢量 PDF，原件完整保留。预览不需要公司 Excel 模板、不生成报销表、不改变账单、核对或提交状态，已提交及已报销费用也可查看。材料、金额或安全裁剪校验失败时明确显示错误，不降级冒充最终打印页。

材料不齐时显示缺项和补材料入口，不生成虚假的最终页。仅支付凭证费用的预览与正式报销包保持相同排版，不同费用始终分别起页；同笔可按原印刷尺寸自动节纸重排。预览缓存检查事项版本、实际源文件内容及排版程序版本；重新读取台账后再次核对缓存。

### 最终报销打印预览

工具栏“报销预览”立即开窗并显示读取/生成状态。没有勾选时，读取当前项目、人员、类别、问题和搜索范围内的全部待提交事项；有勾选时以全部勾选为准，包括隐藏勾选。报销预览固定对应当前侧栏项目，窗口不再提供项目筛选；未选择项目时先提示选择项目，其他项目的勾选不会混入预览。类别仍为与主工作台一致的勾选式多选菜单：顶部“全选”显式勾选当前范围全部类别，之后可逐项取消；部分选择显示半选，再点全选可补齐，取消全选或取消全部选项则恢复全部类别。主工作台筛选和费用勾选保持。点击空白处或按Esc只收起当前菜单。关闭后重开刷新数据并恢复窗口内全部范围，同次打开中重复范围使用缓存。

窗口显示同一份实际PDF渲染出的A4整页：公司模板主表为第一页，只包含原表内容；后面是按表格栏目顺序排列的逐笔材料。同项目、同类别、同报销表子项内连续的合格原生单发票，每张A4上下两张，奇数最后一张单独在上半页；需要额外配套材料的费用保持整组排版。材料字号和完整内容沿用单笔最终排版，不把其他类别放进高铁票空位。“打印预览”打开这份矢量PDF，打印时不包含工作台说明、筛选栏、卡片和链接文字。正式报销包使用相同主表+材料规则，Excel明细及MD页码已计入第一页主表；旧历史文件不重写。

主表由本机已安装Excel隔离、只读导出为单张A4，禁宏、不更新外链、不保存模板；若本机Excel不可用，显示可重试错误，不能用HTML或缩略图冒充最终PDF。材料保持矢量合成，中文可提取，原件保留。预览界面使用统一浅色/深色样式，纸张保持白色；下载HTML内嵌同一组页面图，可离线查看。

预览只读，不核对、退回、提交或确认报销。缺材料费用显示已收到的完整原件，无材料的费用只在主表计费，不伪造凭证页；未核对范围不能因为预览成功而视为已核对。费用/原件/模板/排版版本变化后缓存失效，生成期间变化会拒绝发布过期结果。

### 正式制作报销包

- 仅接收材料齐全、已核对、尚未提交的事项。已提交／已报销／取消事项不纳入新报销包；发现所选事项有同类型、同明确体系的交易编号或相同附件时停止并提示。不同体系订单号不要求相同。尚不等于跨月、不同截图的全面自动防重。
- 首次选择公司模板；当前支持用户提供的“活动运营费用统计表”布局，模板保存在私有 `workspace/工作台/报销模板.xlsx`。换模板会备份上一份。不同结构的模板会明确拒绝，不能随便套写。
- 报销人可修改，报销期间留空则根据已知消费日期填写；未知日期、活动日期、审核签字不猜填。主表费用区只在“现场现金支付（需报销）”列填写分类金额与合计，实际消费金额、公司支付、描述、发票数量及备注等栏留空；无需选择付款来源。原模板名称及表头信息保留，具体购买内容可在“报销明细”查看。
- 已有打印包直接复用；新增打车、外卖、顺丰材料复用原打印助手的识别、裁剪和上下拼版。同一事项顺序连排，不把别的事项填进它的空半页；不支持的格式或金额不一致会提示该事项，修正后再制作。
- 酒店、材料采购的每个原始页面完整缩放至一张 A4；不自动裁掉购买明细，也不把长截图压到半页。材料采购有发票时优先发票，否则采用已核对的扣费记录。长截图应预览确认文字大小。
- 一次输出同名总 PDF、MD 分类费用清单、XLSX 公司汇总表（附“报销明细”工作表及 PDF 页码）。材料超过模板行数时将余项金额合并到最后一行，全部逐笔明细仍在附表；主表发票栏不自动填写。
- 其他原生单发票使用相同的完整单页和旧印刷比例检查；只有同项目、同费用类别、同报销子项连续的费用才可合排。需要付款或其他附件的费用不丢材料、不跨栏目凑页；尺寸未知、额外材料或不能保持字号时保留原排。
- 明确归类为顺丰/快递的费用（包含其他栏目下的顺丰项目）凭正式发票和运单明细核对，不要求付款截图。最终预览、正式报销及材料导出优先核对两份原生PDF的服务商、金额和快递发票号后使用既有安全拼版；上传的付款截图保留在原附件中，不纳入默认打印。显式仅支付凭证和历史打印包仍沿用原要求；不根据模糊名称猜改其他费用。
- 高铁原生单页铁路电子客票，在完整原页保持现有打印字号、没有额外附件且几何能容纳时，同项目同报表子项连续两票拼一张A4，上下放置；不足两张时留空下半页。票号、金额、二维码、页内文字及原件保留，费用仍逐笔计金额，可在Excel/MD明细中共用同一PDF页码。未知票据、多页原票、额外附件、异常旋转/裁剪框或尺寸放不下时按原逐费A4排版，不裁切或缩字凑页。
- **最终总 PDF 按 A4、1×1 打印**，不要再次二合一。Excel 主表设置为单张 A4，明细表横向按一页宽分页；签字栏仍需实际填写。
- 所有文件成功后才提供下载；失败不发布半成品。原件保留。所有文件生成后整批标记已提交并记录文件名；失败不部分提交。此状态是工作台进度，不自动向财务发送文件，到账仍需手动确认。旧导出结果不追溯改状态。

Excel 制作使用本机 artifact-tool 的 Node.js 运行环境，不调用云端模型。当前电脑自动查找 `%USERPROFILE%/.cache/codex-runtimes/codex-primary-runtime/dependencies/node`；迁移机器时需要提供同样的依赖，或配置 `INVOICE_REPORT_NODE`（Node 可执行文件）和 `INVOICE_REPORT_NODE_MODULES`（包含 `@oai/artifact-tool` 的 node_modules 目录）。没有该依赖时会明确报错；仅 `pip install` 尚不能独立提供 Excel 功能。原 `/api/export` 的 PDF＋MD 接口保留用于兼容。

数据保存在 `workspace/工作台/`：SQLite台账、附件、邮件收件和导出文件。原 `processed.jsonl`、归档与机器人任务不被替换。
备份应在退出工作台服务后复制整个工作区，不只复制数据库。真实文件不提交Git。

## 启动与版本核对

`scripts/start-workbench.ps1` 检查 `/api/runtime` 的应用、工作区摘要、后端源码指纹、启动时间、就绪状态和必要能力。后端指纹在进程加载时固定，包含未提交的源码修改；不是每次请求读取当前 Git HEAD。它不证明外部依赖或 Jev 网络服务可用。

- 正确实例且版本/能力匹配才打开页面；`-NoBrowser` 可只进行启动和就绪检查。
- 旧实例（包括没有运行信息接口的旧版本）明确提示需要更新；再次运行启动器不会停掉旧进程。
- 不同工作区、其他 HTTP 服务或已有非 HTTP 监听会报告冲突，不停止未知进程。
- 首次启动若超时则报错，不继续打开无法确认就绪的页面。支持 `-Port` 指定测试端口。

此检查避免把“接口在线”当成“新后端已加载”，不改变 Codex 执行策略。工具拒绝服务操作时，保留拒绝证据，使用允许的人工维护流程；不通过此脚本绕过拒绝。

批量上传前端回归：在已提供 Playwright 和 Chromium 的 Node.js 环境中运行 `node tests/receipt_batch_browser.cjs`。该测试拦截全部测试站点请求，使用合成数据，不访问正式台账；后端回归仍运行 `python -m pytest`。

报销制作前端回归：`node tests/report_browser.cjs`；公司模板集成回归需设置 `INVOICE_TEST_REPORT_TEMPLATE` 为本机私有模板路径，再运行 `python -m pytest tests/test_reimbursement.py`，模板本身不纳入仓库。


## 邮件打车材料自动整理

历史邮件整理器可将同封邮件中平台与金额一致、对应唯一的打车发票和行程单整理为未核对费用。当前发票助手的合成台“补收邮件”采用材料收集流程，不运行该历史自动建费用入口；下载并识别所选项目的材料，在合成台展示建议组合，由用户确认创建。原始PDF保留、金额只算一次，不以开票日期代替消费日期。

已有材料按发票号码、行程文字及文件摘要检查重复；已存在对应费用时补充缺失材料，不重复新增。已提交或已报销费用不自动修改；同一发票号码内容冲突、同金额多组候选、跨邮件无法核对来源、缺少另一份材料等情况留在邮件收件箱并显示原因。合成台的归档适用于任何尚未关联费用的材料，归档或已删除原件再次导入也不会自动复活或新增费用。

此功能不扫描手机订单、不调用模型、不自动提交或报销。关闭工作台后不会后台收取邮件。
# 仅支付凭证的事项

具体事项经确认可以仅凭支付记录报销时，在“材料要求”选择“仅支付凭证（已确认适用）”。仍须上传真实可读取的支付附件，并核对完成，才会进入可提交；普通事项不会因存在支付截图自动放行。修改内容或附件后需重新核对。

这类事项在材料导出及正式报销包中随报销表栏目排列，每笔费用分别起页，不与其他费用混页。付款凭证以原2×2的印刷尺寸为基准；同笔材料可通过重新排列减少页数时自动采用，字号和内容尺寸不缩小、不旋转、不裁切原页。无法减少页数时保留原排法。打印窗口选择A4、每张纸1页，勿再次多页合一；材料导出不改变提交状态，正式制作报销包仍按原流程标记提交。
# 报销流程更新（2026-09-25）

本节描述新增实现。正式服务切换与真实页面验收状态以私有 `TASK.md` 为准，源码测试通过不代表当前运行实例已经更新。

1. 从侧栏“新建项目”或具体项目列表新建／切换。勾选未提交费用后可以批量移动；稳定编号来自后勤项目，金额和附件保留，移动后重新核对。旧名称只在唯一匹配时自动关联。
2. 在材料合成台“收材料”上传，或补收邮件。文件先持久保存，再本地识别；刷新或关闭后仍从合成台继续处理。系统建议在材料合成台就地预览和确认，不直接增加费用。
3. 在合成台查看金额冲突、疑似重复等提示。同屏查看原件和识别内容，选择新增费用或补到已有费用，再确认材料用途。尚未合成的材料不显示“归属不明／归属未定”卡片提示；所属报销项目在确认创建时明确，系统仍不跨项目配对或替用户自动分配未知项目。报销分类在确认创建时选择，商品说明或付款备注缺失不影响配对。补件不增加费用金额。
4. 票据与分笔付款统一在“材料合成台”选择，查看原件、两边合计和差额；明确项目类型、金额及该类型下的项目名称后创建，单侧材料也可以创建。保存后仍需人工核对。旧“确认当前费用金额／分笔付款”及“手动登记”按钮已移除。
5. 合并重复费用时，勾选重复项并点选要保留的费用，先审阅金额和材料。合并保留目标金额，原记录标记已取消并记录去向。它与多份材料归一笔、报表合并展示不同。
6. 在费用表单维护显示简称、报表栏目及展示合并组。HTML、正式Excel和材料清单使用同一汇总快照；同项目雨衣可汇总展示，后台仍保留两笔。商品原文和原件不改。
7. 审阅窗口可试生成并查看实际PDF，试生成不改变状态。材料不齐时补齐，或在核对时明确确认缺项。正式制作仅接受材料齐全或有有效缺项确认的已核对草稿；三份文件全部成功后才标记已提交，不代表已发送财务或到账。侧栏与嵌入页不再提供经验管理入口或管理弹窗。

酒店二维码：支持已验证的上海税务发票交付入口。领取原始PDF后进入收件队列；未知网站、过期或需登录时提供原领取入口，不将二维码图片当发票。不支持线上开票不等于完全不能开票。

打印：PDF内部已完成排版，并与报销表栏目顺序一致。除合格原生单发票同项目同类别同子项上下两张一页外，其他费用分别起页；同笔票据及付款截图可以按现有印刷尺寸重新排列以减少页数；相同页数保留原位置及顺序。补充材料保持原来的完整A4比例，不推断裁剪边界。预览、材料导出和正式报销包共用此规则；打印窗口选择A4、每张纸1页。其他已验证配套布局保持不变，未经验证的边界不裁切。

运行：启动器校验前后端源码、工作区及能力。新版支持正常退出后重载，并通过工作区锁阻止在不同端口重复启动。旧版没有正常退出接口时会报错，不打开旧版或强行终止进程。切换前应停止旧实例。

维护切换：`scripts/integrate-workbench.py` 默认只检查；显式 `--apply` 要求8765和8766均已停止、主目录源文件仍与恢复基线一致。它先备份数据库、附件和原源码，再复制变化文件、迁移唯一项目关联，核对金额、状态、附件关联及哈希。备份恢复函数在 `workbench_migration.py`，只能停止工作台并备份较新数据后调用。不要把私有备份或台账加入Git。

## 独立项目工作台兼容入口

`/agent` 保留上一版独立项目界面以兼容已有链接；当前主入口为原工作台 `/`，不从主导航跳往独立界面。原工作台已经具备项目导航、新建项目、材料查看、费用详情、智能整理及原报销预览。

「材料查看」包含本项目尚未整理及已经关联费用的材料，可搜索、按状态筛选并打开原件及识别字段。「费用详情」显示具体报销名称、商品、类别、金额、核对状态和所附原件；右侧详情区可查看首张预览，也可打开完整多页原件。切换项目会清空旧详情，不将未归属或其他项目材料显示为当前项目。

「整理进度与待确认」优先展示缺少事实的任务，显示原件、商品、金额、商家和对应选项。确认沿用现有原件版本绑定与剩余额度，在同一个任务中继续生成预览。右上角「人工工作台」和核对入口保留；新页面不自动核对、提交或改变原件，后台仍使用现有脚本和 Agent，没有引入 Pi。

## 邮箱自动收件与 Agent 整理

在 `/agent` 的「邮箱自动收件」中可开启、暂停或立即检查已在本机配置的163邮箱。授权码仍由本机凭据管理器保存，网页不接收授权码。保持电脑和发票助手服务运行，默认每两分钟检查一次新邮件；退出后暂停，重新启动后按保存的进度继续。

邮件中的 PDF、照片、压缩包及已支持的发票领取链接先保存原件，再交现有 Agent 整理。主题或正文只明确提到一个完整项目名称时自动归属；否则询问项目。可在收件设置中明确指定该邮箱的默认项目，该规则不跟随当前浏览的项目，也不继承到另一个邮箱或文件夹。

Agent 结合商品、金额及商家证据整理，缺少同笔关系时在原任务中提问，确认后使用剩余额度继续生成报销预览。后续邮件补到同项目尚未创建费用的待处理任务时，同样沿用原任务和额度。整理结果均为未核对草稿；人工工作台入口及人工核对、正式制作报销包流程保留。

收件进度按账号、文件夹和邮箱 UIDVALIDITY 隔离，重复邮件或重复文件不重复创建费用；不会扫描历史收件目录。网络超时和连续失败会有限重试后暂停，可修复网络或授权后点「立即收件」恢复。附件损坏、领取链接失效或缺少材料时保留已收到的原件并提示处理，不将部分收件当作完整费用。未知网站或需登录的链接仍需补充原件。

## 手机同一 Wi-Fi 联通

电脑版右上角「手机连接」可开启局域网二维码入口，手机上传、查看和核对共用当前电脑账本。默认关闭，退出助手后需重新开启；详情见 [手机联通说明](phone-lan.md)。

同一入口也可选择「异地访问 · Tailscale」，通过私人网络访问这份账本。首次需要在手机绑定电脑账号并连接 Tailscale，随后打开完整手机配对链接；详情见 [异地访问说明](phone-remote.md)。
