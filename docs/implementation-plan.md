# 网约车发票排版工具实现方案

状态：第一阶段已实现，并于 2026-09-03 通过自动化测试、类型检查、滴滴与曹操真实单页样例视觉验收和真实重复件验证。163 邮箱只读导入已完成真实账号连接验收。2026-09-04 已完成飞书机器人真实长连接联调，并加入三层留存模型的第一阶段。

## 目标

在 Windows 本机批量处理已支持平台的网约车 PDF。每个票据组包含一份电子发票和一份可含多页的行程单。程序裁掉行程单的装饰区及无用空白，校验平台与金额后，把同组逻辑页按一列两行拼成 A4 打印包。

拼版序列固定为：全部行程单页按原顺序排列，电子发票页最后。每两个相邻逻辑页生成一张 A4 打印页，不同票据组绝不混排。

当前真实样例支持滴滴、曹操和享道；未验证的平台使用通用结构证据识别，证据不足才进入“需要检查”。可选的 163 IMAP 功能只读下载相关 PDF，后续识别和拼版仍在本机完成。第一阶段不发送或修改邮件、不使用云端 AI、不处理扫描件、不控制打印机，也不制作 EXE、ZIP 或安装程序。

## 项目位置与运行方式

项目目录：

```text
<你的开发目录>\invoice-print-layout
```

第一阶段从源码运行：

```powershell
python -m invoice_print_layout process --workspace .\workspace
```

项目采用 Python 3.12、`pyproject.toml`、`src/` 布局、Typer 命令行和 pytest。PDF 读取与矢量拼版使用 PyMuPDF；金额使用 `Decimal`，配置使用 Python 标准库读取 TOML。

## 工作区

程序首次运行时创建：

```text
workspace\
├── 待处理\
├── 已完成\
├── 已归档\
├── 需要检查\
├── 交付\
├── config.toml
├── mail163.toml
├── mail_imports.jsonl
├── 长期索引摘要.md
└── processed.jsonl
```

`config.toml` 保存用于输出文件名的固定姓名；`mail163.toml` 只保存邮箱地址和只读文件夹名称。客户端授权码仅保存在 Windows 凭据管理器。所有工作区数据均由项目 `.gitignore` 排除。

## 163 邮箱导入

1. 使用 `imap.163.com:993` 和 SSL 连接，登录后发送网易要求的 IMAP ID。
2. 使用只读方式打开邮箱文件夹，并通过 `BODY.PEEK[]` 读取邮件，避免标记已读。
3. 默认只检索最近 30 天，只有主题或附件名包含“发票”“行程”的 PDF 才进入“待处理”。
4. 附件必须具有 PDF 文件头；用 SHA-256 与已有待处理、归档和异常附件去重。
5. 不删除、不移动、不标记服务器邮件，不发送邮件。
6. CLI 中邮箱导入和打印处理仍是两个独立命令；飞书“打车”会串联当天导入和既有的严格打印处理，无法可靠配对的文件仍进入“需要检查”。

## 飞书机器人入口

1. 仅支持企业自建应用的长连接模式，不开放本机 HTTP 端口，也不要求公网 IP、域名或内网穿透。
2. App Secret 仅保存在 Windows 凭据管理器；工作区配置只保存 App ID 和已绑定用户的 Open ID。
3. 首次启动生成六位绑定码；绑定完成后，仅处理该用户发给机器人的单聊消息。
4. 长连接事件处理器只把消息放入本机队列，文件下载、PDF处理和结果上传由单个后台工作线程串行执行。
5. “打车”只读检查当天163邮件并自动处理新 PDF；只有未找到新附件时才开启手动上传批次。“开始 外卖”仍创建手动批次，使用“处理”结束；不同批次不混合。
6. 使用飞书 `message_id` 和文件 SHA-256 去重；原始附件按批次保留。
7. 结构完整且唯一配对的网约车 PDF 可自动进入处理链路。图片和淘宝外卖批次保守转入“需要检查”，等待离线 OCR 与外卖匹配能力完成。
8. “记忆”刷新并返回长期索引摘要，同时列出超过七天的工作记忆清理候选；第一阶段不执行删除。
9. 每次处理成功后，把本次各票据组的完整打印包顺序追加为一份总 PDF，并同时生成一份 Markdown 费用清单；机器人最终只发送这两个交付文件。

## 三层留存模型

1. 工作记忆：当前批次、已结束机器人批次和临时副本。超过七天后只进入清理候选。
2. 留存材料：原始电子发票、行程单、打印包和异常证据。根据公司财务或审计政策留存，不自动删除。
3. 长期索引：`processed.jsonl` 中的结构化记录及其可重建的 `长期索引摘要.md`，用于检索、统计和去重，但不替代原始凭证。

第一阶段使用确定性的结构化字段和 Markdown，不引入向量数据库、AI 摘要或定时清理。任何真实删除都需要单独实现复核与确认流程。

## 文件识别与配对

1. 只读取 `待处理` 中的 PDF，不修改原文件。
2. 使用可提取文字分类：已知平台可由标题直接识别；未知平台必须同时具备行程单标题、行程合计及上车时间、起点、终点、金额等表格结构。包含电子发票关键字段的文件视为电子发票；不依赖文件名猜测。
3. 从行程单提取行程合计，从电子发票提取价税合计，统一为精确到分的 `Decimal`。
4. 优先按“出行平台 + 金额”形成唯一的一对一对应；平台未知但同金额候选唯一时允许配对，打印包使用“网约车”命名，并在费用清单标记“新平台待命名”。
5. 金额不一致、同金额存在多个候选、文件无法分类、PDF 损坏、加密、扫描或关键字段缺失时，不进行猜测，转入 `需要检查`。
6. 使用发票号码和原始文件 SHA-256 指纹识别重复件；重复件不再次生成打印包。

## 行程单裁剪

电子发票不做内容裁剪，只使用完整可见页面。

行程单逐页处理：

1. 使用 PDF 文字块、图片和矢量绘制对象确定内容边界，不转为图片。
2. 首页定位已支持平台的行程单标题；裁剪起点位于标题上方 10 至 15 pt。
3. 保留申请日期、手机号、行程日期、行程数量、总金额、表头和全部行程明细。
4. 顶部平台 Logo、广告、推广二维码以及底部页码允许删除。
5. 横向默认保留完整页面宽度，避免裁掉较长的起点和终点。
6. 底部裁剪线位于最后一个有效表格或文字对象下方 10 至 15 pt。
7. 续页没有标题时，必须通过可确认的表头、表格边框和正文对象确定边界；不能确定时整组进入 `需要检查`。

## 一列两行拼版

输出打印页为纵向 A4，分成上、下两个等高槽位。每个逻辑页保持比例，以矢量方式放入对应槽位并居中，不拉伸、不截断正文。

算法等价于：

```text
逻辑页 = [行程单第1页, 行程单第2页, ..., 电子发票]
打印页 = 每次从逻辑页中顺序取2页，放入A4的上、下槽位
```

示例：

```text
行程单1页：A4第1页 = 行程单1 + 发票
行程单2页：A4第1页 = 行程单1 + 行程单2
             A4第2页 = 发票 + 空白
行程单3页：A4第1页 = 行程单1 + 行程单2
             A4第2页 = 行程单3 + 发票
```

每个票据组单独生成打印包，因此不会用另一个报销事项填补空白槽位。

## 输出、归档和异常

打印包名称：

```text
YYYY-MM-DD_平台_金额元_姓名.pdf
```

日期取开票日期。发生合法同名时增加 `_2`、`_3`，不覆盖现有文件。

成功后先重新打开输出 PDF，验证页数、A4 尺寸、关键文字和金额；验证通过后再完成以下操作：

```text
已完成\2026-01-15_滴滴_123.45元_张三.pdf
已归档\2026-01-15_滴滴_123.45元_张三\
├── 原始电子发票.pdf
└── 原始行程单.pdf
```

异常件使用独立目录保存原文件和 `原因.txt`。重复件进入 `需要检查\重复件`。每次运行生成 `本次处理结果.txt`，记录成功、异常、重复数量和文件位置，并自动打开 `已完成` 目录。

同一次处理中有一个或多个成功票据组时，在 `交付` 目录生成同名的一份总 PDF 和一份 Markdown 费用清单。总 PDF 只顺序追加完整打印页，不重新进行跨票据组拼版；费用清单列出逐项金额、分类合计和总计。只有两个文件都生成并通过校验后，机器人才能把它们作为本次最终输出发送。

输出采用临时文件加原子重命名：只有输出验证成功后才移动原始附件，避免程序中断造成半成品或丢失输入。

- `documents.py`：分类、字段提取、金额配对和行程正文边界。

- `storage.py`：安全写入、归档、配置和处理记录。
- `cli.py`：用户命令和本次处理摘要。

不在第一版引入数据库、Web 服务、插件系统、任务队列或 GUI。

## 测试与验收

自动化测试使用程序生成的虚构 PDF，不提交真实票据：

1. 行程单和发票分类。
2. 金额精确匹配、金额不一致和同金额歧义。
3. 单页、两页、三页行程单的拼版顺序。
4. 裁剪后所有正文文字仍在页面内。
5. 输出为 A4，文字仍可提取，内容未被栅格化。
6. 输出重名、重复件和中途失败的恢复行为。
7. 异常原因和处理记录完整。

本机验收已使用用户提供的滴滴和曹操真实单页样例，渲染输出后完成视觉检查。多页行程单目前通过虚构的 1、2、3 页测试验证；在拿到真实多页样例前，不能宣称多页真实模板已验收。
