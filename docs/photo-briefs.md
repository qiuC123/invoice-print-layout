# 飞书照片简报

工作台“现场照片 → 飞书简报”可启用或关闭本项目推送，并单独选择附带三列照片审阅 PDF。旧项目默认不自动启用照片附件；用户启用后发送到已绑定的本人飞书账号。

## 照片审阅 PDF

- 横向三列，每页最多六张，按工厂装货、现场车辆、人员及其他类别分组。完整水印保留，编号在本次审阅册中固定，照片下标注拍摄时间、分类和原图状态。
- 定时及手动补读的附件使用本轮 `photo_ids` 中已归档照片，包含重复记录；简报的新增数仍只计算 `added_ids`。依据不足、项目归属未确认的照片只统计待核对数量，不上传图片。
- 读取日期是群消息日期，照片实际拍摄日期另标注；不把补读或重复照片宣称为当天新增。零张已归档也生成一页处理结果，不填入旧照片。
- 每 24 张最多一份 PDF，避免单附件过大；图片用于预览压缩，保留画面及水印，原照片文件不改。审阅册保存在私有 `workspace/现场进度/<项目ID>/审阅册/<投递ID>/`。
- 页面可查看已生成 PDF。“读取全部来源群并发送审阅”按选择的一天读取本项目所有已配置来源群，完成后沿用简报设置发送。现有照片试用汇总不重新采集。
- 该 PDF 是审阅材料；日报与结算 PPT 继续沿用固定模板，不自动替换模板内容。

## 日常使用

- 先配置项目照片来源群和自动分类，并在“待办事项 → 定时任务”设置读取时间。
- 简报发送到现有飞书机器人已经绑定的本人账号，不发送到微信群或飞书群。应用凭据仍从现有系统凭据存储读取，不下发到浏览器。
- 到时开始读取，整理结束后推送；18:00 是开始时间，简报时间取决于本次处理耗时。
- 关闭浏览器不影响运行；电脑、微信和工作台服务仍需运行。
- 新启用不自动补发此前的历史任务；普通“读取微信群”不会触发简报，须使用明确标注“并发送审阅”的补读入口。

## 结果含义

定时简报汇总本次新增照片记录，其中“已归档”和“待核对”分开统计。重复条数、读取或识别未完成事项另列。一个群读取失败时其他群仍继续，简报如实显示部分完成。服务中断或任务失败会发送未完成结果；零新增也会说明情况，不等同于群内没有图片。

试用简报汇总项目当前已有照片，明确标注并非今天新增，且不会重新读取微信群。卡片只发送项目名、日期、数量、分类和处理状态。启用 PDF 后，附件包含已归档照片及其水印、车牌等审阅标签；不发送整群聊天或 OCR 原文，不把本地路径当作手机可访问链接。

照片数量不用于推算施工完成率、出勤人数或实际完成工序；日报、结算报告继续遵循用户模板。

## 投递与恢复

简报内容和接收账号在入队时固定。定时运行记录与简报一一对应；发送成功后保留飞书 message_id，重复调度或重启不会重复生成该简报。试用汇总相同内容重复点击也复用同一记录。

卡片和每份 PDF 分别使用固定 UUID，单独持久保存 message_id；上传 file_key 也保存。附件失败后只继续未完成部分，已经送达的卡片和附件不再发送。短暂连接失败后最多尝试三次，间隔至少一分钟。进程中断的发送有十分钟占用期，附件推进时续期；恢复仍使用原 UUID。首次发送超过 45 分钟且状态未确认的记录停止自动重发，显示“送达状态待核对”。仅卡片送达时明确显示“简报已送达，PDF尚未全部送达”。全部附件取得回执才显示全部送达。

关闭推送取消尚未发送/重试的队列；已经提交给飞书的发送不能撤回。重新绑定飞书账号后，原账号的待发简报不会转发给新账号。

配置及简报记录位于私有 `workspace/后勤/tasks.sqlite3` 的 `photo_brief_settings` 与 `photo_briefs` 表。分类源文件不变，照片任务新增关联照片 ID，用于准确计算本轮新增和去重；每个微信来源群有独立读取目录。

## 当前范围

已接通单项目定时简报、三列照片 PDF 附件，以及工作台启停、试发和按日补读发送入口。飞书内“添加微信群”、卡片内在线照片核对、手机访问本机工作台尚未实现；本机 localhost 链接不作为跨设备入口。

验证涵盖默认关闭、本人接收、项目隔离、正常/部分/失败/零新增、两群读取、重复调度、重启、断网重试及超过去重窗口停止重发，并覆盖页面设置和试发状态；新增 PDF 分组与拆分、源文件完整性、附件失败续传、重复照片纳入和待核对照片排除验证。真实按日补读已取得简报及 PDF 发送回执，首次实际定时执行仍待到点检查。
