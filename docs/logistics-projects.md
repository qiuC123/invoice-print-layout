# 项目待办与辅助消息

入口：工作台 `/logistics`。本页需要加载新版 Python 后端；旧进程只刷新网页不能加载新 API。

## 使用方式

1. 左侧点击“新建”，只填项目名称即可，例如项目一、项目二；工作地点选填，仅用于显示。项目名称在本工作区内不能重复。
2. 左侧只列出项目，不再附加“全部消息”或群用途按钮。消息通过顶部“消息收件箱”进入；具体群使用消息页的“微信群”筛选，标题显示所选群名。将筛选恢复为“全部群”和“全部分类”可查看当前项目已入库的照片与报销辅助资料，切换项目也会清除筛选。群用途仍在“微信群”页面管理。项目选择会保存在浏览器中，刷新不改变当前项目。
3. 在“微信群”点击“添加微信群”，填写群名称、用途，可先保存。用途包括现场沟通、订餐、住宿、票据、其他；已有群可以调整用途、补充绑定。
4. 接收工具验证成功后，在“补充绑定”填写本人账号及会话稳定标识。两个标识必须同时填写；昵称不能代替稳定标识。已绑定的会话不能改成另一个会话，保留历史来源。
5. 消息可按群和业务分类筛选。共享群或共享联系人同时属于多个项目时，消息进入左侧“待归属收件箱”；在消息下展开“调整归属 / 分类”，选择正确项目。

建项目和填群信息不会启动询问、发消息或订餐。草稿项目尚未设置负责人、起止日期，不能生成定时任务。当前原事项台账仍从单独入口打开，本次没有迁移历史票据或住宿表。

## 删除任务

临时任务和定时任务卡片右上角均使用红色“×”删除，左侧不再显示完成/启用的小方块。“编辑”“标为完成 / 重新打开”“暂停任务 / 启用任务”各自独立。

删除后可通过提示中的“撤销删除”恢复。删除定时任务会关闭其启用状态并取消尚未启动的排队记录；已开始读取的照片继续处理，不删除照片或报销资料。恢复的定时任务保持暂停，需点击“启用任务”才恢复调度。删除和恢复均校验项目与版本，过期页面不能覆盖更新。

## 定时任务与临时任务（2026-09-26）

待办页分为两类：临时任务使用“标为完成 / 重新打开”按钮、日期和备注；定时任务当前用于每日读取飞检照片，可设置北京时间（最多12个）、开始/结束日期、来源群和启用状态。原有事项自动归为临时任务。

定时执行由工作台后端承担，关闭浏览器页不影响执行，但电脑、微信和本地服务需保持运行。后台每10秒检查到期事项，读取所选群当天照片，沿用项目OCR、Jev与归档设置，跳过重复图片。来源群来自现场照片设置，与普通聊天收件绑定分开；保存定时任务不会启用全群聊天读取。

按任务/日期/时间保存唯一执行记录，避免重启或反复检查重复触发。照片任务正在运行时排队；当天晚启动补读当天最近一个到期时点，不追补之前日期。读取中重启会显示中断，可到现场照片手动补读；失败或待核对不标作全部完成。每个任务显示最近结果，可刷新查看。点击“暂停任务”停止后续执行，已经开始的读取继续完成。

例如可按项目需要设置每日18:00及开始/结束日期。具体时间不写死在源码；定时任务创建与实际执行结果分别以页面及执行记录为准。

## 当前工作方式（2026-09-26）

- “待办事项”替代原“后勤安排”：按项目新增、编辑事项与备注，选填截止日期，点击“标为完成 / 重新打开”，按未完成/已完成/全部筛选。保存后刷新仍保留。旧订餐调度表不改，不把勾选待办转成发送指令。
- “消息收件箱”作为现场照片和发票报销的辅助入口。页面请求 `scope=support`，后端在查询和500条上限之前只选择当前项目 `materials`、`invoices` 两类已有资料；历史其他分类保留。待归属资料仍单独核对。
- 这不是全群采集，也没有接通普通聊天的按需读取。辅助区提供“读取现场照片”和“处理发票报销”入口，保持当前项目。后续普通聊天读取应围绕具体材料限定群、日期和所需信息，不重读全群历史。
- 照片可由用户点击“读取微信群”手动触发，也可在待办页配置每日定时读取，按所选群和日期读取本机图片缓存；开启自动分类后继续OCR、Jev分类和归档。保留文件夹读取；没有实时监听全群消息。
- 待办 API：`GET /api/logistics/todos?project_id=...`、带 token 的 `POST /api/logistics/todos`。更新必须携带当前 revision；跨项目和过期修改拒绝，避免覆盖他人更改。

## 保存和隔离

本机 `workspace/后勤/tasks.sqlite3` 保存项目、群绑定、微信来源消息、手动归属记录、读取进度和独立的 `project_todos` 待办表。原消息保持不变；人工分类另外保存。UI 每次提交带明确项目 ID，快速切换时旧响应不能覆盖新项目。

2026-09-23 用户确认交互原型后，正式界面对齐左侧项目和用途导航、右侧消息卡片、群管理及后勤安排（后勤安排已于2026-09-26改为手动待办），支持系统浅色/深色与手机布局。原型中的示例项目、群和消息没有写入真实台账。

群用途与消息分类是两个概念。群用途用于整理会话；正文中的明确词语可把现场群里的消息归为餐饮、住宿、票据或进出场资料。混合主题和不明确内容留待分类，不自动猜业务数量。专用群中的简短回复可继承该群用途，但并不等于已经确认订餐。

图片、语音、系统消息等保留来源与类型；本次没有新增 OCR、媒体下载或云端上传。引用文字单独展示，不拿引用里的旧数量当作当前回复。本人发出的消息和收到的消息区分展示；身份无法核验时显示方向未知。

默认展示当前范围最近 500 条，超过时显示总数及截断提示，筛选只针对已加载消息。此版本尚无历史分页入口。

## 接收模块与实机边界

`wechat_inbox.WeChatInbox.receive_batch()` 将完整历史窗口和读取进度在同一事务保存；账号加来源消息标识去重，冲突回滚，人工归属不会被重复采集覆盖。满窗口、过期、分片缺失或身份未知时可以保留消息，但不推进读取进度。

`collect_once()` 只调用显式绑定且未暂停项目的会话，失败保留上次进度；下次读取重叠 120 秒。它是可调用的单次读取模块，尚未连接常驻循环。调用前必须独立验证微信当前账号，不能把配置表单或目录名当作身份核验证据。接收 API 未开放给网页任意导入来源。

2026-09-23 实机测试：微信 4.1.15.12 的数据库密钥仍未匹配成功，没有读到真实聊天，没有启动持续监控。页面明确显示未联通。消息分类、去重、跨项目隔离以合成样例测试，不代表微信接收端到端通过。
