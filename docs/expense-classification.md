# 自动费用分类与本地经验

2026-09-25，用户授权把原先逐笔“建议→采用→保存”改为自动判断并保存费用类别；必要文字按需发给 Jev 的范围扩展为此自动流程。原始 PDF/图片仍只在本地提取，不上传整张票据、整库数据或凭据。

## 使用方式

新版服务加载后，工作台打开时会串行处理尚未核对的待分类事项。新增事项默认“其他”；保存凭证、补材料或修改用途后会重新检查。无需逐笔点击建议按钮。关闭页面后不持续扫描，没有新建系统定时任务或常驻模型任务。

明确类别自动保存，左侧类别及材料要求随之更新。用户在判断期间编辑备注时保留未保存内容；如果手动改了类别，保留手动选择。正在打开的登记/确认弹窗会暂停新的自动请求。

“材料采购”是费用类别；“待补材料”是报销材料完整性状态。自动分类不补造发票，不自动核对金额、提交报销或确认到账。例如材料采购仍缺发票或支付记录时，类别已经改变，但仍显示待补材料。

人工明确选择的类别、已核对或已提交的事项不被自动覆盖。系统自己分类过的未核对事项在明细变化后可重新判断；信息不足、货运规则缺失、混合类别、附件读取不完整、模型异常时保留待处理提示。相同资料的失败不循环调用模型，补充资料后再尝试，或点击“重试自动分类”。

旧后端尚未重启时保留兼容入口，“采用并保存分类”会直接保存并刷新，不再只填表。但自动队列和经验库必须加载新版后端才生效。

## 经验机制

- 同一事项资料不变：保存处理结果，刷新页面/重启服务不重复识别或调用模型。
- 不同事项的商品/服务文字和用途完全相同（忽略空白及英文大小写）：复用本地结果缓存，不重复请求 Jev。商品提取/OCR仍可能需要执行，缓存不等于完全不用识别。
- 用户对已识别内容手动纠正类别，或点击“核对完成”：相同内容的人工确认经验优先于模型缓存。
- 不同人工确认互相冲突时停止自动套用，要求补充用途或人工分类。空白、仅笼统日用百货的内容不生成通用经验。
- 不按商家名称直接套用，不把相似但不同的商品当成同一内容；用途不同则独立判断。历史账目不自动猜测为训练标签。

这是持久的本地经验/缓存，不是模型在线训练；模型自己分类过多次也不会自动升级为人工确认。规则、类别定义或模型版本改变时，输入键变化，旧结果不直接混用。状态存在私有工作台 SQLite 的 category_attempts/category_experience 表中，禁止提交真实内容到 Git。

## 技术边界

`GET /api/state` 返回 category_auto_ready 和逐项 classification 状态。页面只对 pending 项调用 `POST /api/category/auto`，接口沿用 Host/Origin/token 保护。识别与模型请求不占全局写锁；写入前重新核对事项/附件，并在 SQLite 事务内只更新类别及相关核对状态，防止覆盖并发保存的新字段。同一服务实例串行分类，多标签页不会同时调用模型；整个工作台仍按单实例使用。

原 `POST /api/category/suggest` 保持只读兼容。人工保存/核对可产生经验反馈，自动保存不会冒充人工确认。

模型设置沿用 `jev-1.13.0`、Choice、20秒网络超时；固定类别为材料采购、酒店、高铁、外卖、打车、顺丰、其他。置信度低于0.8不自动采用；阈值不是经校准的准确率。凭据沿用 TYPESAFE_API_KEY/JEV_API_KEY 或本机 typesafe.env，不记录密钥。

测试覆盖自动保存、重复请求/重启缓存、跨事项内容复用、人工纠正、冲突、空内容、资料变化、失败不循环、跨进程写入比较、接口权限，以及页面自动刷新和未保存编辑保护。合成验证不代表所有陌生票据都能首次正确分类。
