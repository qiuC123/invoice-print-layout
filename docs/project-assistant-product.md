# 项目助手产品草案

状态：2026-09-26 用户已确认先接通单项目定时照片简报。定时简报、工作台启停及试发已实现，见 `photo-briefs.md`；飞书内来源群绑定和正式导航调整仍待后续实施。

## 产品定位

用户添加项目的微信来源群，电脑按项目规则整理照片，完成后在飞书收到一条简报。日常使用以结果为中心；电脑工作台承担核对、纠错、归档、报销和维护。

飞书机器人会话保留两个主要入口：每日简报、添加微信群。待确认事项出现在简报中，需要处理时再展开，不增加常驻收件箱、识别设置、日志等入口。

## 使用流程

1. 进入指定项目，选择本机微信读取器已识别的群。显示群名称及足以区分同名群的信息，服务端保存稳定群 ID；仅输入名称不能直接完成绑定。
2. 每天北京时间 18:00 由电脑现有调度开始处理当天照片。完成后生成本次整理结果，推送到该项目明确配置的接收会话。执行失败也需要一条可行动的结果，不能假装已完成。
3. 简报包含日期、项目、按拍摄时间对应的阶段、已归档照片数量与类别、待核对或未完成事项。重复照片不计入新增，其他项目不计入本项目。
4. 无需处理时看完简报即可；存在问题时查看依据，并在合适的核对界面修正。手机不能通过电脑的 localhost 地址访问工作台，第一版不能把本地链接当作跨设备可用入口。

## 展示边界

| 飞书日常入口 | 电脑工作台 | 后台维护 |
| --- | --- | --- |
| 添加、查看本项目来源群 | 查看照片、分类纠错、目录归档 | 读取器连接、账号状态 |
| 接收每日照片整理简报 | 发票报销、报表预览与导出 | OCR、文字分类服务配置 |
| 简报内展开少量待确认事项 | 临时待办、定时任务调整 | 运行记录、错误原因、来源证据 |

消息收件箱保留为照片和发票的辅助来源记录，后续从日常主导航退到后台维护入口；不建设全群聊天聚合器。上述导航调整是草案，本轮不直接移除正式功能。

照片仍由本机微信读取器按指定群、日期有界读取。飞书不直接读取微信群。本地目录读取功能保留。群内有多个项目时逐张核对水印项目、地点和来源；工厂装货照结合项目及运输关联，不简单排除外地工厂。

现有链路为本地 OCR 提取文字、Jev 判断分类、原文件保存；不从照片数量编造施工完成比例或具体进度。日报和结算报告仍按用户固定模板单独制作，只替换照片的约束不变。

## 第一轮试用范围

先复用现有照片调度与分类结果，为一个项目、一个明确接收人接通飞书简报，再增加来源群选择交互。接入时复用 `feishu_bot.py` 的长连接和网关基础，但必须补齐项目到接收会话的绑定、简报渲染、投递与失败重试记录、重复投递防护和按钮回调。

飞书长连接主要服务既有发票/住宿消息；照片简报复用现有应用和本人绑定，通过工作台后台独立投递。原型仍是示例；正式试用状态以 TASK.md 和私有投递回执为准。

## 验收标准

- 用户无需打开后台，即可在已识别群中给项目添加来源，并看到绑定结果。
- 定时任务完成后收到一次归属正确的简报；重复执行或重启不会重复发送同一结果。
- 完成、部分完成、失败、没有新增照片四种情况都如实表达，异常可以追溯。
- 共用群其他项目照片不被纳入；待核对记录不计入已归档，简报不声称照片证明了施工完成率。
- 手机入口不依赖电脑 localhost 地址；本机离线时不误报整理成功。
