# 在工作台外新增 agent 知识层

在工作台外新增由发票项目管理的 agent 知识层，用于整理已有审计、人工分类、偏好和识别纠正，补记决定的理由与可复用的查证办法。知识只存放在 Git 忽略的 `workspace/agent-knowledge/` 私有目录，真实业务内容不进入公开仓库。整理器只读工作台，不改变业务数据；工作台仍是唯一的业务写入入口，也不重复实现已有的分类经验机制。

每条知识保留来源记录的编号、可获得的日期和决定者；用户原话逐字保存，模型归纳标为「推断」，冲突标为「有冲突」。缺失的理由和决定日期不补造。草稿先进入 `pending/`，试点期由用户采用后才生效，采用前在 `history/` 留存快照；发票 agent 不读取未采用草稿。生效知识通过 `INDEX.md` 索引商家、项目、办法和先例页面，只帮助寻找证据，不能代替原件或用户决定。同一时间只有一个整理器写入。

ADR 0003 的工作记忆、留存材料与长期索引仍负责材料留存和定位，留存期限、原件保全及删除边界不变；agent 知识层是其外部的解释与经验补充，不替代这三层。P0 只完成摸底、私有目录骨架和旧决定补记草稿，不引入向量数据库、自动采用、定时整理或业务写回。

## P1：手动整理与采用

用户手动调用 [invoice-consolidate](../../skills/invoice-consolidate/SKILL.md)，只通过绑定工作区身份的 CLI GET 读取来源，并在私有目录 `pending/` 中生成页面替换稿、`state.json` 和 `SUMMARY.md`。审计/识别纠正用 SQL ID 游标；疑点全状态、分类尝试、经验和偏好用稳定键与内容指纹检测覆盖和消失，不伪造时间游标。跨页固定快照指纹，变动则重取。经验和偏好复用 `/api/preferences` 的完整只读快照，不调用 apply；分类保留已删除和无项目费用。

流程：**运行技能 → 审查 `pending/SUMMARY.md` → 明确采用或退回**。没有新增/变化/消失记录时仅返回 `nothing`，不写文件。

```text
python scripts/knowledge_adopt.py adopt --knowledge <私有知识目录>
python scripts/knowledge_adopt.py reject --knowledge <私有知识目录> --reason <退回意见>
```

采用先复制当前知识到 `history/<UTC时间戳>-before-adopt/`（排除 pending/history），再按文件替换草稿，包括摘要；最后把 `pending/state.json` 的 `adopted_through` 写入正式状态，保留其他字段并清空 pending。删除知识条目通过页面替换表达，被推翻内容保存在待删除说明中，不直接删除整页。退回保留正式状态，追加 `history/rejections.md` 后清空 pending；下次仍从上次采用位置读取。

单文件替换是原子的，普通写入异常回滚并保留快照/草稿；断电或强制终止可能留下混合页面，需要人工根据快照恢复后重试。同一知识目录只允许一个操作方。P1 不运行定时器、不接飞书、不发送消息、不自动采用，不执行真实知识整理；公开文件和测试仅含通用说明与合成数据。
