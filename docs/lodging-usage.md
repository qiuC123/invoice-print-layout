# 本地住宿逻辑与使用范围

住宿报销可在工作台按酒店费用整理：选择项目，上传发票和所需材料，确认金额及人员后创建待核对费用，再按正常核对、制作报销包流程处理。手机材料使用[手机连接](phone-lan.md)，邮箱发票使用收件邮箱。

## 保留的本地能力

- `lodging.py` 保留住宿字段解析、日期／晚数／价格校验、金额与下次付费日期计算，以及 SQLite 草稿和业务结果记录。`LodgingService` 通过 `LodgingBackend` 接口操作记录；当前没有随应用提供的登记后端，也没有独立页面或 CLI 入口。
- `lodging_capacity.py` 保留住宿总人数及增减人数解析、已确认房间容量和空位预览。房间或入住人数不明确时要求补充；人数减少只提示核实，不自动退房或合并房间。
- 工作台后勤待办可保留住宿人数核对任务和本地提醒，不会自动登记住宿或办理付款。

这些本地逻辑不代订酒店、不分配人员，也不会自动生成报销费用。不要将代码层能力当作已经上线的住宿登记功能。

## 开发验证

使用合成数据运行 `python -m pytest tests/test_lodging.py tests/test_lodging_capacity.py`。测试覆盖字段校验、草稿与恢复、重复请求，以及人数和容量预览；不操作真实住宿记录。
