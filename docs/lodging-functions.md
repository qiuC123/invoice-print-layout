# 住宿第一版功能与字段清单

2026-09-22；第 1 步设计交付。沿用现有住宿登记规则，新增项为实施建议，未修改线上表。

## 第一版操作

| 操作 | 输入与处理 | 执行者 |
| --- | --- | --- |
| 试算 | 单价、正整数晚数；不填日期也可算金额，不创建记录 | 公式/脚本 |
| 新开登记 | 明确要求登记、起算日期、晚数、单价；房号选填 | 脚本校验和写入 |
| 续住登记 | 明确对应住宿及本次起算日期、晚数、单价；新增一段，保留上一段 | 脚本 |
| 补房号 | 明确记录 ID 或唯一匹配的住宿；补充房号，不新建费用 | 脚本 |
| 修改登记 | 明确目标和改动；回显变更，保留修改记录，不覆盖旧确认快照 | 脚本 |
| 查询/汇总 | 按项目、酒店、人员、日期查询；只读，未知日期单列 | 脚本 |
| 取消未提交请求 | 取消当前草稿任务，不删除已存在住宿 | 脚本 |
| 识别自由口语 | 识别试算/新开/续住/修改/查询/取消草稿/补充/不明确/其他 | 规则优先，Jev 候选 |

登记只记录住宿安排，不表示酒店已接受预订，不表示付款或已报销。正式退订、已付款记录冲销、复杂换房、自动付款、跨月财务结算及自动报销关联不在第一版。

## 一行记录的含义

建议一行表示「同一酒店的一间房在一段固定单价期间的住宿」。多人同住列人员名单；多间房拆行，不把人数乘进房费。同一期间不同单价拆段。房号未知时仍用独立记录 ID 区分；酒店+房号也不能跨时间自动合并。

续住单价不自动沿用：用户明确说沿用且原记录唯一、单价已知时可以引用，并在结果中回显来源；日期仍需本次明确指定或澄清，不按旧表到期日擅自顺延。

## 字段

| 字段 | 当前状态 | 第一版建议 |
| --- | --- | --- |
| 房号 | 已有选填文本 | 保持选填，不用作唯一标识 |
| 业务类型 | 已有新开/续住 | 保持 |
| 起算日期 | 已有 | 写入必填；试算可空；相对日期按消息时间/北京时间解释并回显 |
| 入住晚数 | 已有 | 正整数；不能从总价倒推 |
| 每晚单价 | 已有 | 金额用 Decimal，正数、最多两位小数；变价分段 |
| 应付金额 | 已有公式 | 单价×晚数，程序交叉核对，不让模型计算或写公式结果 |
| 下次付费日期 | 已有公式 | 起算日期+晚数，不直接等同实际退房或已付款 |
| 项目、酒店 | 待新增 | 可先存草稿；多人正式登记时要求确定，历史未知留空 |
| 入住人员 | 待新增 | 名单可先留空后补；查询人员时不猜；首版用文本，后续按需要建人员表 |
| 登记人 | 待新增 | 后台从飞书身份填，模型不能指定；创建人不等于入住人 |
| 来源任务标识 | 待新增 | 后台填写，写入去重及超时回查使用；同一消息可有多条带序号记录 |
| 前段住宿标识 | 待新增 | 续住关联来源，不以房号单独匹配 |
| 实付金额/实际付款日期 | 已有后台字段 | 本版不自动填，原值保留 |
| 备注 | 已有 | 可作补充说明，不能代替权限和去重字段 |

线上字段变更在第 3 步形成具体变更及备份清单后执行，本轮未新增。项目/酒店等必填要求是多人版建议，不追溯阻止旧七列登记。

## 脚本、Jev、Codex 边界

- 表单/固定命令、金额日期、查重、权限、字段完整性、表格读写和回复模板全部由脚本处理。
- Jev 仅对规则未能可靠解释的消息做意图选择。返回结果是候选意图，不是授权或业务执行结果；缺资料、多个目标和无权限仍由脚本阻止写入。
- 普通追问采用缺字段模板。任意酒店名/人员名的准确抽取不属于本轮 Jev 意图测试；不能因分类通过就声称已能一句话登记。
- Codex 不进入日常必经流程；用于开发维护或后续明确需要的复杂临时任务。

## 待用户使用反馈再定的细节

多人角色的名单及项目范围、酒店是统一字典还是自由文本、已登记错误如何由管理人修正，在第 3/4 步联调前确定。本轮先采用上述建议完成测试设计，不擅自填入公司真实人员。

## 第 1、2 步的完成边界

第 1 步交付为此清单；第 2 步需同一批合成指令上的规则结果、Jev 实际结果、延迟、输入用量与费用估算。凭据不可用时只能交付离线结果，不能宣称 Jev 已验证。
