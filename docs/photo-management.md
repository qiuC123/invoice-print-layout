# 项目照片管理

在项目工作台选择项目，打开“现场照片”。各项目的照片、来源设置和保存目录分别保存。

## 日常操作

1. 点击“导入照片”，或展开“采集照片”。文件夹读取包含子目录；微信群按所选群和消息发送日期读取本机缓存。
2. 在“采集与归档设置”开启当前项目的自动分类，并填写项目城市。之后每次导入、读取文件夹或读取微信群，新照片都会执行本机 OCR → Jev 判断 → 分类保存。图片本身不上传；仅将提取文字、项目、来源群名和相关已确认记录发给既有 Jev 接口。其他项目默认关闭。
3. 明确的结果自动保存；其余照片显示“待核对”及原因。可选中后点击“识别所选照片”重试，也可打开“核对与分类”补充或修改字段。类别可选车辆、人员、其他；归档环节可选进场、展期、撤场。车辆另填写车牌、批次日期及工厂/现场。人员姓名和岗位可留空。
4. 确认归属当前项目后，点击“保存核对结果与照片”。页面显示实际保存路径。
5. 已保存照片可以再次“查看 / 调整分类”；改分类后写入新目录，旧分类副本只有在内容未变时才移除。归档原件始终保留。

车辆保存结构：`保存目录/车辆/阶段/车牌-批次日期/工厂或现场/照片`。人员与其他照片按`保存目录/类别/阶段/拍摄日期/照片`保存。工厂拍摄日期可以早于车辆到场批次日期。

## 识别和质量

- 拍摄日期来自照片水印，微信群读取日期来自消息时间，两者不能混用。
- Jev分别判断项目归属、照片类别和工厂/现场；必需判断的置信度至少0.9且日期、排期、车牌及批次等必要字段齐全，才自动归档。置信度不是实测准确率。水印模糊、文字缺失、多个日期或车牌时需要核对；模型故障、超时或保存失败保留原件和可重试记录。
- 以前人工核对过的水印项目简称可作为项目名称参考。共用群不能直接当作项目归属证据。工厂照片应结合明确项目或来源群与已确认车辆关联；工厂所在地可以不是项目城市。工厂运输批次使用同车、同环节且拍摄日之后31天内的唯一已知批次，不把工厂拍摄日直接当作到场日。
- 项目阶段按拍摄时间与项目排期计算，不交给模型猜测。搭建、展期、撤展分别对应进场、展期、撤场；搭建前标为前期准备。撤展起点采用项目配置的具体日期和时间；边界当天缺具体时间时留待核对。消息发送日不替代拍摄日。
- 页面区分“自动分类并保存”和“已核对并保存”；自动结果也能手动修正。已保存记录重新识别不会覆盖分类或重排文件夹。重复导入不会再次调用模型；待核对项通过“识别所选照片”显式重试。
- 原件不裁剪、不加水印。完全相同文件按 SHA-256 去重；同一照片的不同清晰度版本可能分别出现。
- 微信优先读取本机 `_h` 原图版本；只有普通缓存时明确标注。WXGF 保留原缓存并生成 PNG 显示副本。没有缓存、资源对应关系不唯一或解码失败会列出未完成项；可以在微信中打开/下载图片后重读，或直接导入文件。
- 不推断人员身份、岗位或完整出勤时长，也不能把逐图人数相加当作实际出勤人数。
- 普通导入与手动读取由点击触发；另有可选每日定时读取及飞书简报，见下文和照片简报文档。均不是全群实时监听，也不会自动修改日报或结算模板。

## 本机读取器维护

本地上传、文件夹读取、OCR 不依赖微信。微信群读取使用工作区私有 `photo-reader.json` 配置：`python`、`helper_dir`、`audited_source`、`helper_hashes`、`media_sha256`、可选 `ffmpeg`。配置指向已核对的本机读取模块，校验模块哈希及当前登录账号，密钥只在读取进程内存中使用。配置和照片数据不能提交到代码仓库。

图片读取单次最多 500 张、单张最多 20 MB；微信日期范围最多 31 天。服务重启会保留已完成照片，并将未完成任务标为中断，可重试去重。

## 每日定时读取

待办事项 → 定时任务可配置每日时间、来源群和起止日期。工作台后端到点调用现有读取流程；本机微信需登录，图片仍受本机缓存是否可用的限制。结果展示新增、重复和待核对数量；不自动下载微信未缓存的原图，不把定时读取当作实时监听。手动微信群及文件夹读取继续保留。
