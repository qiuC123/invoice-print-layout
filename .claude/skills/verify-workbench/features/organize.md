# 自动整理与配对

开启上传后自动整理时，新增的发票与付款图片经过本地识别和规则配对，生成待核对费用；金额相等、有明确商家关系的一对材料应成为一笔草稿，不替用户核对。

## 子功能

- `F3-recognize`：真实 PDF 取字与 PNG OCR 得到金额、商家、付款状态。
- `F3-pair`：每组发票＋付款截图配成一笔，金额守恒。
- `F3-offline`：模型关闭、任务模型调用为零，10 笔仍为待核对草稿。

## 用户怎么进入

- 在设置的 `自动整理` 中开启 `上传后自动整理`，关闭 `复杂问题使用 AI 模型`；本技能空工作区已预置同样配置。
- `F2` 的每种新增上传会自动触发整理。自动整理面板平时隐藏，仅待确认、失败、停止、启动/刷新失败或关闭自动整理时显示；正常完成的任务以只读 `/api/agent/jobs` 留证。
- 助手中的手动整理/重试、人工回答复杂问题、材料合成台手动 `寻找合成组合` 和 `确认合成并进入待核对` 不是自动上传路径，本轮未执行。

## 用 Playwright 操作

前提：甲项目完成 F2 的全部新增上传。完整命令 `verify.cjs run <新名称>`，检查段为 `F3-local-organize-match`。

- 不点内部工具或直接调用写 API，等上传自动触发的真实任务完成 → `/api/agent/jobs` 留 `F3-jobs.json`，每个任务 `models=0`、`use_model=false`。
- 关闭合成台、刷新甲项目 → 待核对列表出现 10 笔，金额 31–40 元。
- 逐笔只读检查真实 `/api/state` → 均有 `invoice` 与 `payment` 两种附件，`material_match.alignment_status=balanced`，`verified=false`、`stage=draft`，总额 355 元。
- 留 `F3-real-paired-drafts.*`；最终 `originals.json` 对比保存后的附件与上传前 SHA-256。

## 坑

- 不准用项目测试里的预识别 `queued/auto_queued` 或数据库 seed；那些夹具绕过本功能的真实识别路径。
- 模型关闭不等于脚本伪造成功，必须看到真实任务和材料关联。没有任务、只有收件材料时，本功能失败。
- 缺前提时保留失败，不能人工造费用使后续核对看似通过。
- 费用类别和原文疑问以本轮 `F3-real-paired-drafts.state.json` 为准；配对与金额通过不代表自动分类通过，不能直接修产品来迁就样本。
- 未检查：多对多、混合优惠、缺材料、歧义问答、20 份以上批次恢复、AI、外部分类服务。
