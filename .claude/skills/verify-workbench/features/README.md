# 发票工作台功能地图

这是主要网页入口“发票助手”（`--mode invoice`）的验证地图。其他后勤扩展没有纳入本轮。先读上级 [SKILL.md](../SKILL.md)，再按本页进入功能文件。

## 基础前提

- `verify.cjs start <新运行名称>` 从空数据目录启动，实际地址取 `.runtime/verify/<名称>/session.json` 的 `base`，不猜端口。
- 数据只在本次目录 `data/`；10 组虚构原件在 `materials/`。所有项目、配对与核对状态都必须通过网页建立。
- `verify.cjs doctor <名称>` 通过；页面按钮事件和自动整理助手加载完毕；AI 与复杂问题模型辅助关闭、上传后自动整理开启、邮箱关闭。
- `.venv` 可联接到共享环境，源码必须来自当前工作树 `src`。Chromium 使用临时 profile，不复用用户浏览器；本流程视口为 1440×1000，不代表移动端验证。

## 操作约定

- 自动完整流程：`node .claude/skills/verify-workbench/scripts/verify.cjs run <新运行名称>`。分步 `start → doctor → drive → stop` 见技能正文。
- 五个功能有顺序依赖：项目→材料入口→本地整理配对→核对→报销包。不跳过入口失败，不预造后续费用来凑通过。
- 优先无障碍名称、现有元素 ID 与 `data-item`；原生隐藏文件输入由可见按钮触发的 `filechooser` 接受。
- 拖放用稳定目标的边界计算落点，不硬编码屏幕坐标；CDP 交付真实文件/目录路径，不伪造目录枚举接口。
- 页面重载时先等待新 URL 和页面体检，避免在旧文档上点击。

## 证据和跳过的报告

- 每个入口单独记结果，截图＋ARIA＋服务状态；操作日志和 HTTP 写响应说明做过什么，刷新/GET 状态说明结果确实保存。
- PDF 实际下载后提取文本和渲染，核对固定预期页数；不只看界面缩略图或接口页数。
- 原件哈希保持；清理仅删除本次实例/素材，留下证据与清理回执。
- 结果为“通过 / 失败 / 确认进不去”；没执行写“未检查”。失败应区分地图遗漏、脚本错误、环境缺失、产品问题，并列尝试和缺少的前提。
- 原生 OS 文件窗口和浏览器目录上传确认在当前 Playwright 脚本中“确认进不去”：已试 filechooser 接受目录，无法在 page DOM 操作原生窗口；文件选择后的真实上传、递归读取仍单独验证。

## 功能列表

1. [项目](projects.md)：新建、日期、侧栏切换、右键修改项目时间。
2. [收材料](intake.md)：收材料、导入文件夹；主页面/合成台的文件与目录拖放。
3. [自动整理与配对](organize.md)：本地 OCR 和规则、草稿与金额守恒。
4. [核对](review.md)：逐笔、连续下一笔可见、退回再核对。
5. [报销包](print-package.md)：单笔/整批预览、矢量 PDF 与包文件。
